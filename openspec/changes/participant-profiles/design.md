# Design

## Context

Участники сегодня — строки в `episode.yaml` (`host`, `guests`), попадают в индекс (`episodes.host`/`episodes.guests`) и выводятся на карточке и странице выпуска. Сущности участника нет. Предыдущий change `episode-host-guests` прямо объявил «структурные объекты участников (имя + био)» Non-Goal — этот change его снимает.

## Goals / Non-Goals

- Goals: каталог участников с описанием и аватаркой; страница участника со списком его выпусков; интерактивные имена в списках участников выпуска; аватар хранится один раз.
- Non-Goals: админка и загрузка файлов через веб (сервис по-прежнему file-driven); авторизация; правка фидов (`itunes:author` остаётся канальным); распознавание «кто есть кто» в старых описаниях выпусков (ручной перенос имён в `host`/`guests` уже был сделан автором в предыдущем change).

## Decisions

### D1: файлы участников — `people/<slug>/person.yaml`

Каталог в корне `podcast-dir`, рядом с `podcast.yaml`: `people/<slug>/person.yaml` (обязателен), `avatar` — имя файла изображения в той же папке, описание — `description` в yaml либо `description.md` рядом (приоритет у `description.md`, предупреждение при обоих — симметрично эпизодам). Slug = имя папки, `^[a-z0-9]+(-[a-z0-9]+)*$`, иначе — ошибка рескана (так же строг, как сканер эпизодов: неизвестные файлы в папке участника — ошибка, dot-файлы игнорируются, неслужебные папки в корне `people` сканер эпизодов не трогает). `name` — непустая строка, ключ связи; имена участников уникальны, дубликат — ошибка рескана. Папки `people` нет → фича целиком выключена, сайт работает как раньше.

### D2: связь по имени, пересчёт при каждом Sync

Совпадение: имя участника (`person.yaml:name`) = строка из `host`/`guests` эпизода после трима, точное совпадение. Связь живёт в индексе (таблица `episode_people`: выпуск, участник, роль `host`/`guest`, позиция в списке гостей), поэтому страница участника собирает выпуски одним запросом. Пересчёт — целиком в транзакции каждого `Sync` (удалить все связи эпизода, вставить заново по текущим `host`/`guests`) — идемпотентно, исчезнувший участник просто перестаёт быть связанным, ошибка не возникает. Имена без совпадений остаются строками — так же, как сейчас.

### D3: хранение в БД

Миграция `0006_people.sql`: таблица `people` (slug PK, name UNIQUE, description, avatar_ext, file_path аватара) и `episode_people` (number, slug, role, position; PK (number, slug, role); FK на `episodes.number` и `people.slug` с CASCADE). Аватар в БД не кладём — раздаём файл с диска; в `people` храним расширение для URL.

### D4: URL и маршруты

- `GET /people/{slug}` — страница участника: аватар (если есть), имя, описание (безопасный markdown, тот же пайплайн, что у эпизодов), выпуски участника новыми сверху; неизвестный slug → 404.
- `GET /people/{slug}/avatar.{ext}` — раздача файла аватара из папки участника; Content-Type по расширению; расширение фиксировано конфигом участника, любой другой путь → 404. Канонический URL стабилен, аватар заведён один раз и переиспользуется всеми выпусками участника.
- `GET /api/people` — машинный список: `slug`, `name`, `url`, `avatar` (если есть), `episodes` (номера выпусков).
- `GET /api/episodes` — аддитивное поле `participants` (роль, имя; для известных участников — slug, URL страницы, URL аватара); `host`/`guests` не меняются, старые потребители API совместимы.

### D5: интерактивность на сайте

На карточке выпуска и странице выпуска линии «Ведущий:» и «Гости:» рендерятся поэлементно: известный участник — ссылка на `/people/<slug>`, неизвестный — обычный текст. Архив не трогаем: строка выпуска целиком является ссылкой, вложенные ссылки недопустимы (уже устоялось в `episodes.html`). Карта сайта пополняется страницами `/people/<slug>`; фиды и SEO-разметку выпусков не меняем.

### D6: страница участника

Новый шаблон `person.html` (layout + страница, как у эпизодов): заголовок с аватаром и именем, описание (rendered markdown), список выпусков участника карточками с ролью («Ведущий»/«Гость») — новые сверху. Служебные страницы (`404` и т.п.) не заводим — отдаётся существующий 404-ответ.

## Risks / Trade-offs

- Имя как ключ связи: переименование участника в `person.yaml` разрывает связи, пока автор не поправит `episode.yaml` — принято (как и в episode-host-guests: имя — источник правды). Митигируется предупреждением в README.
- Смешанный рендер (ссылки + текст) усложняет шаблон линий участников — частичный шаблон с поэлементным выводом.
- `people/` в корне `podcast-dir` — новая сущность для валидатора корня: сканер эпизодов игнорирует нецифровые папки, отдельная проверка структуры `people` не ломает эпизоды.

## Migration Plan

1. Миграция `0006` аддитивна; после деплоя таблицы пусты до первого рескана.
2. Рескан сканирует `people/` и пересчитывает `episode_people`; сайт начинает линковать участников, как только автор заведёт папки.
3. Откат: `Down` миграции удаляет таблицы; до удаления файлов `people/` сервис работает без участников.
