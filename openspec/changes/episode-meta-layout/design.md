# Design

## Context

Сейчас эпизод — это один файл, чьё имя несёт идентичность (`YYYY-MM-DD-slug.mp3`), а опциональный sidecar уточняет метаданные. Модель не выражает «один выпуск — несколько носителей»: второй формат в папке — ошибка синхронизации, видео невозможно. Полный мотивационный разбор — см. proposal.md; ключевые решения приняты в ходе explore-сессии с автором сервиса и зафиксированы ниже.

## Goals / Non-Goals

**Goals:**

- Папка-номер как единица публикации и единственный идентификатор (URL, guid, ключ индекса).
- Обязательный `episode.yaml` как источник заголовка, даты и описания носителей.
- Поддержка 0..1 audio + 0..1 video, отдельный видео-фид.
- Раздельные счётчики по носителям, сумма в UI; явные ссылки на скачивание.
- Одноразовая миграция плоской папки (m4a-only) на сервере.

**Non-Goals:**

- Веб-плеер видео и бикон просмотра видео (только скачивание).
- Сохранение guid/статистики при переходе (осознанный разрыв, fresh-start БД).
- Автонумерация выпусков сервисом: папки создаёт автор, номер — его решение.
- Транскодирование, валидация содержимого носителей (bitrate/resolution — декларативные).
- Админка: управление по-прежнему только через файлы.

## Decisions

**D1. Идентичность — номер, slug упраздняется.**
Имя папки (`^[1-9][0-9]*$`, без ведущих нулей) = первичный ключ эпизода в SQLite, сегмент URL и основа guid. Внутренний суррогатный `id` и slug исчезают: одна сущность вместо трёх. `007` и `0` — ошибка синхронизации (автор явно имел в виду выпуск), нецифровые имена — игнор. Альтернатива (номер только в папке, slug в meta) отклонена: два идентификатора вместо одного, ради совместимости guid, которую автор отказался сохранять. Следствие: переименование папки = удаление + новый эпизод (сброс счётчиков) — правило прежнее, объект сменился.

**D2. `episode.yaml` — обязательный манифест.**
Поля: `title` (обязателен), `published_at` `YYYY-MM-DD` (обязателен), `description` (опционален), секции `audio:`/`video:`: `file` (обязателен в секции), `duration` (секунды, опционален), `bitrate_kbps`/`resolution` (опциональны, информационные). Сканер проверяет структуру и существование файлов; характеристики не валидируются и ниоткуда не выводятся (оценка по битрейту остаётся фолбэком `itunes:duration` только для аудио). YAML с ошибкой — ошибка синхронизации, как раньше с sidecar.

**D3. Носители: таблица классификации.**
`audio:` = `.mp3|aac|m4a` → MIME `audio/mpeg|audio/aac|audio/x-m4a`; `video:` = `.mp4|mov|mkv|webm` (MIME: `video/mp4`, `video/quicktime`, `video/x-matroska`, `video/webm`). Файл в секции обязан иметь расширение своего kind; неупомянутый недот-файл в папке — ошибка (молчаливое игнорирование уже однажды маскировало опечатки). Dot-файлы (scp-временки) игнорируются всегда. Таблица — одна карта в коде, новый формат = строка.

**D4. Два фида с guid на носитель.**
`/feed.xml` — эпизоды с аудио (enclosure `/audio/{n}`, guid = enclosure URL); `/feed-video.xml` — эпизоды с видео (enclosure `/video/{n}`, guid = `/video/{n}`). Один эпизод с обоими носителями живёт в обоих фидах независимо: подписчики фидов не пересекаются, guid per-фид корректен. `itunes:episode` = номер, `itunes:duration` — из meta носителя, иначе оценка 128 kbps для аудио. Сортировка фидов/сайта/API — по `published_at` desc; номер порядок не задаёт (дата — источник истины для ленты).

**D5. Схема: номер как ключ, носители в отдельной таблице.**
`episodes(number PK, title, description, published_at, discovered_at)`; `episode_files(number, kind 'audio'|'video', file_path, mime, size, duration_seconds, bitrate_kbps, resolution, file_mtime, UNIQUE(number, kind))`; `download_events` получает колонку `kind` в уникальный индекс `(number, kind, ip_hash, ua_hash, day)`; `play_events` — без изменений. Миграция (goose) пересоздаёт таблицы; существующие данные не переносятся — fresh start согласован (guid всё равно умирают). Откат миграции в goose-стиле — `Down`-секция восстанавливает прежнюю схему (пустую).

**D6. Скачивание — те же URL, отдельный эндпоинт не нужен.**
`/audio/{n}` и `/video/{n}` уже отдают файл с Range; ссылки «скачать» в UI ведут на них же (подкаст-приложения так же качают enclosure). Заголовок `Content-Disposition: attachment` не ставим — он ломал бы стриминг в плеере по тому же URL; браузер предложит «сохранить» сам, а кнопка на сайте может использовать атрибут `download` якоря. Раздельные счётчики получаются бесплатно: каждый URL = свой kind.

**D7. Миграция — скрипт на CT, до деплоя новой версии.**
`scripts/migrate-to-numbers.sh`: (1) стоп контейнера, (2) `data/heavytech.db` → sidecar-имя с датой, (3) каждый плоский `YYYY-MM-DD-slug.m4a` → папка `<n>/` с номером по хронологии даты (1 = старейший, ties — по имени), файл переносится как есть, (4) генерация `episode.yaml`: `title` из слага прежним алгоритмом (Capitalized Words), `published_at` из имени, `duration` — `ffprobe`, если доступен (на CT его может не быть — тогда поле опускается, это допустимо), (5) итоговый отчёт. Слот `podcast.yaml` не трогается. После скрипта — деплой новой версии (ansible-роль, bump ref — отдельный шаг вне репозитория сервиса), рескан на старте пересобирает индекс.

**D8. UI/API.**
Карточка эпизода: «Выпуск №7», дата словами, заголовок/описание, суммы скачиваний (audio+video) и прослушиваний, аудиоплеер (`data-episode="7"`), список ссылок «скачать» по носителям с размерами; видео без плеера. API-элемент: `number`, `title`, `description`, `published_at`, `media: [{kind, url, size, duration}]`, `downloads: {audio, video, total}`, `plays`. Бикон `/track/play` меняет payload `slug` → `episode` (номер).

## Risks / Trade-offs

- [Разрыв guid у подписчиков: дубли выпусков в приложениях] → осознанно принято; задокументировать в README («после миграции старые ссылки не резолвятся»).
- [Автор забудет next-number и создаст дублирующую папку] → невозможно: имя папки занято файловой системой; конфликт проявится как обычный существующий эпизод.
- [Номера разъедутся с датами (вставные выпуски)] → сортировка по дате, номер — только идентификатор; расхождение легитимно.
- [ffprobe недоступен на CT → meta без duration] → поле опционально, `itunes:duration` оценится по размеру; заполнить можно позже руками.
- [Строгая валидация папок (лишний файл = ошибка рескана) блокирует публикацию из-за мелочи] → сознательно: тишина уже маскировала ошибки; dot-файлы исключены, остальное — сигнал автору убрать.
- [Миграция выполнена на живой папке при работающем контейнере] → скрипт требует остановки контейнера первым шагом и проверки отчёта до запуска новой версии.

## Migration Plan

Порядок на сервере (выполняется в apply): стоп контейнера → `scripts/migrate-to-numbers.sh` на CT → проверка отчёта и структуры папок → bump `heavytech_git_ref` в infra → `make run --limit heavytech` → smoke-проверки фидов/страниц на проде. Откат: возврат старого ref (приложение вернётся к slug-модели, но папки уже новые — обратная миграция папок не автоматизируется, принимается: выпуски восстановятся из бэкапа `data/`).

## Open Questions

Нет — все развилки закрыты в explore-сессии (идентичность-номер вместо slug, без ведущих нулей, m4a в парах, один общий change, скрипт-миграция на сервере).
