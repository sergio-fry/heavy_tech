# Spec Delta: episode-publishing

## ADDED Requirements

### Requirement: Эпизод — это папка с номером и обязательным episode.yaml

Система MUST распознавать эпизод как подпапку папки подкастов, имя которой — номер выпуска. В папке MUST лежать `episode.yaml` с `title`, `published_at` и хотя бы одной media-секцией (`audio:`/`video:`), указывающей `file:` на существующий файл. Номер — единственный идентификатор эпизода в URL, guid'ах и индексе. Нарушение любого правила (нет meta, битые поля, несуществующий файл, некорректное цифровое имя) — ошибка синхронизации; нецифровые имена папок игнорируются.

#### Scenario: Новый эпизод попадает в индекс

- **WHEN** в папке подкастов создана папка `7` с `episode.yaml` (`title`, `published_at: 2026-11-01`, `audio: {file: zapis.m4a}`) и файлом `zapis.m4a`, выполнен рескан
- **THEN** в индексе появляется эпизод номер 7 с заголовком и датой из meta, доступный через сайт, фиды и API

#### Scenario: Папка без meta — ошибка синхронизации

- **WHEN** существует папка `8` без `episode.yaml` и выполнен рескан
- **THEN** рескан завершается ошибкой синхронизации, индекс остаётся в последнем консистентном состоянии

#### Scenario: Meta ссылается на несуществующий файл — ошибка

- **WHEN** `episode.yaml` папки `7` указывает `audio.file: net-communichego.m4a`, которого в папке нет, и выполнен рескан
- **THEN** рескан завершается ошибкой синхронизации

#### Scenario: Некорректное имя папки из цифр — ошибка

- **WHEN** в папке подкастов появилась папка `007` и выполнен рескан
- **THEN** рескан завершается ошибкой синхронизации

#### Scenario: Нецифровая папка игнорируется

- **WHEN** в папке подкастов есть папка `chernoviki`, выполнен рескан
- **THEN** эпизод не создаётся, сервис продолжает работать

### Requirement: Носители ограничены и классифицируются по расширению

У эпизода MUST быть не более одного аудио- и одного видеоносителя: секции `audio:` и `video:` в meta. Классификация — по расширению: `.mp3`/`.aac`/`.m4a` — аудио, `.mp4`/`.mov`/`.mkv`/`.webm` — видео; файл в секции MUST иметь расширение своего kind. Характеристики (duration, bitrate, resolution) информационные — сканер проверяет только существование файлов. Не упомянутый в meta файл (кроме dot-файлов) — ошибка синхронизации; dot-файлы игнорируются.

#### Scenario: Аудио и видео одного выпуска

- **WHEN** папка `7` содержит `audio:` на `zapis.m4a` и `video:` на `efir.mp4`, оба файла существуют, выполнен рескан
- **THEN** эпизод 7 проиндексирован с двумя носителями: аудио MIME `audio/x-m4a`, видео — по расширению `.mp4`

#### Scenario: Аудио-файл в video-секции — ошибка

- **WHEN** `video:` ссылается на `zapis.m4a` (аудио-расширение), выполнен рескан
- **THEN** рескан завершается ошибкой синхронизации

#### Scenario: Неупомянутый файл — ошибка

- **WHEN** в папке эпизода лежит лишний `staraya-zapis.mp3`, не указанный в meta, выполнен рескан
- **THEN** рескан завершается ошибкой синхронизации

#### Scenario: Dot-файл игнорируется

- **WHEN** в папке эпизода лежит `.zapis.m4a.gSNpVJ` (временный файл копирования), выполнен рескан
- **THEN** эпизод публикуется без ошибок

### Requirement: Номер после публикации неизменяем

Номер эпизода MUST фиксироваться папкой при первом обнаружении. Переименование папки опубликованного эпизода MUST трактоваться как удаление старого эпизода и добавление нового (новый guid, сброс счётчиков эпизода). В документации к сервису это поведение MUST быть явно описано.

#### Scenario: Переименование папки меняет идентичность эпизода

- **WHEN** папка `7` переименована в `9` и выполнен рескан
- **THEN** эпизод 7 исчез из фидов и сайта, появился эпизод 9 с нулевыми счётчиками

## MODIFIED Requirements

### Requirement: Индекс синхронизируется с папкой

Система MUST при старте и по запросу `POST /admin/rescan` приводить индекс SQLite в соответствие с содержимым папки подкастов: новые папки-эпизоды индексируются, исчезнувшие — удаляются из индекса (вместе с их появлением в фидах и на сайте; события метрик сохраняются). Повторный рескан без изменений в папке MUST быть идемпотентным.

#### Scenario: Рескан после добавления и удаления

- **WHEN** в папку добавлена новая папка-эпизод, а одна существующая удалена, и вызван `POST /admin/rescan`
- **THEN** индекс содержит новый эпизод и не содержит удалённый; повторный вызов рескана не меняет индекс

#### Scenario: Индекс восстанавливается после потери

- **WHEN** SQLite-файл удалён и сервис перезапущен
- **THEN** индекс эпизодов полностью восстановлен сканером из папок (метрики при этом начинаются с нуля)

## REMOVED Requirements

### Requirement: Эпизод обнаруживается по имени файла

**Reason**: Идентичность эпизода больше не выводится из имени файла: папка-номер и обязательный `episode.yaml` заменяют конвенцию `YYYY-MM-DD-slug.<ext>`, а носители перестают быть одним файлом.
**Migration**: Одноразовый миграционный скрипт сворачивает плоские файлы в папки-номера (хронологическая нумерация) и генерирует `episode.yaml`; выполняется на сервере до деплоя новой версии.

### Requirement: Sidecar-файл уточняет метаданные эпизода

**Reason**: Sidecar `<slug>.yaml` заменён обязательным `episode.yaml` внутри папки эпизода: заголовок и дата больше не выводятся из имени файла, длительность и характеристики принадлежат носителям.
**Migration**: Миграционный скрипт переносит `title`/`description` из старых sidecar-файлов в генерируемый `episode.yaml` (для выпусков, где sidecar был).

### Requirement: Слаг после публикации неизменяем

**Reason**: Слаг упразднён вместе с filename-конвенцией; роль стабильного идентификатора перешла к номеру эпизода.
**Migration**: Новое требование «Номер после публикации неизменяем» воспроизводит правило для папок-номеров.
