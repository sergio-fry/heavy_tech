# Spec Delta: audience-metrics

## MODIFIED Requirements

### Requirement: Скачивание считается один раз на клиента в сутки

Система MUST засчитывать скачивание носителя эпизода при успешном `GET /audio/{номер}` или `GET /video/{номер}` не-HEAD-запросом и не более одного раза в сутки (UTC) на комбинацию (эпизод, носитель, хеш IP, хеш User-Agent). Скачивания аудио и видео MUST учитываться раздельно по носителям. Повторные запросы той же комбинации в те же сутки, включая Range-продолжения той же докачки, MUST увеличивать счётчик только на первом запросе.

#### Scenario: Докачка не раздувает счётчик

- **WHEN** один клиент в течение дня запрашивает аудио эпизода 7 тремя Range-запросами
- **THEN** счётчик скачиваний аудио эпизода 7 вырос ровно на 1

#### Scenario: Аудио и видео считаются раздельно

- **WHEN** один клиент в течение дня скачал аудио и видео эпизода 7
- **THEN** счётчик аудио вырос на 1, счётчик видео вырос на 1, оба независимы

#### Scenario: Новые сутки — новое скачивание

- **WHEN** тот же клиент запрашивает тот же носитель на следующие сутки
- **THEN** счётчик вырос ещё на 1

### Requirement: Ботовые и HEAD-запросы не считаются

Запросы методом HEAD и запросы с User-Agent, похожим на краулер/монитор (шаблоны `bot`, `spider`, `crawler`, `monitor`), MUST не засчитываться как скачивания — ни аудио, ни видео. Запросы без User-Agent MUST также не засчитываться.

#### Scenario: Проверка доступности не считается

- **WHEN** мониторинг делает `HEAD /audio/7` и `HEAD /video/7` каждый час
- **THEN** счётчики скачиваний не изменились

#### Scenario: Краулер не считается

- **WHEN** запрошен `GET /audio/7` с User-Agent `SomeBot/1.0`
- **THEN** счётчик скачиваний не изменился

### Requirement: Прослушивание фиксируется биконом плеера

Веб-плеер на сайте MUST отправлять `POST /track/play` при старте воспроизведения эпизода (бикон указывает номер эпизода); система MUST записывать событие прослушивания с опциональным процентом прогресса. Для неизвестного номера MUST возвращаться 4xx и событие не записывается. Повторные биконы одного эпизода в сутки от одного браузера не обязательны к дедупликации.

#### Scenario: Клик по play увеличил счётчик

- **WHEN** посетитель нажал play у эпизода 7, плеер отправил `POST /track/play` с этим номером
- **THEN** событие прослушивания записано, счётчик прослушиваний эпизода 7 вырос на 1

#### Scenario: Бикон по неизвестному эпизоду отброшен

- **WHEN** отправлен `POST /track/play` с номером 999
- **THEN** ответ 4xx, событие не записано

### Requirement: Счётчики видны на сайте и в API

Сайт и JSON API MUST показывать по каждому эпизоду суммарные скачивания за всё время как сумму по носителям (аудио + видео), а JSON API дополнительно — разбивку скачиваний по носителям; прослушивания показываются суммарно по эпизоду. Агрегаты MUST вычисляться из сырых событий запросами, без предвычисленных счётчиков в индексе эпизодов.

#### Scenario: Числа согласованы

- **WHEN** у эпизода 7 три скачивания аудио и одно видео, одно прослушивание, запрошены `GET /` и `GET /api/episodes`
- **THEN** оба представления показывают downloads=4; API дополнительно показывает audio=3, video=1, plays=1
