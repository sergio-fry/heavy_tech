# Proposal

## Why

Выпуски интервью — ядро подкаста, но у эпизода в meta нет полей об участниках: кто ведущий и кто гости. Сейчас имена гостей живут только внутри свободного текста описания, поэтому их нельзя показать на карточке выпуска структурно (сайт показывает сплошное описание), и на 49 существующих выпусках участники «зашиты» в описания в разнородных формах («Гость выпуска — X», «Кто в выпуске: …», «Участники: …»).

## What Changes

- В `episode.yaml` появляются опциональные поля участников: `host` (строка) и `guests` (список строк, порядок = порядок вывода). Поля необязательны: нет — линии на карточке не рисуются. Валидация мягкая: непустые строки, ничего не выводится из имён файлов.
- Индекс хранит участников (`episodes.host`, `episodes.guests` JSON-массив), API отдаёт `host` и `guests`, карточка на сайте получает строки «Ведущий: …» и «Гости: …» под описанием — каждая только при непустом поле.
- **Миграция контента — ручной проход по 49 выпускам** (решение автора): значения переносятся из описаний в поля руками, описания при этом правятся тоже вручную — автосервис не режет текст. Сервису достаточно принять новые поля; для контроля прогресса ручного прохода в README даётся grep-рецепт (какие папки ещё без `host`/`guests`).
- Фид не меняется: `itunes:author` остаётся канальным, участники — поверхность сайта и API.

Допущения: пустая строка `host` или отсутствие `guests` = «не указано» (без подстановки автора канала по умолчанию — автор и так показан в герой-блоке); порядок гостей в meta сохраняется в UI и API; HTML-экранирование значений — общими механизмами шаблона.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `episode-publishing`: новое требование — meta может описывать участников выпуска (`host`, `guests`), мягкая валидация, сквозной порядок гостей.
- `podcast-serving`: карточка выпуска на сайте получает строки ведущего и гостей; JSON API — поля `host` и `guests`.

## Impact

- Код: `scanner.go` (разбор опциональных полей meta), миграция `migrations/0003_*.sql` (ALTER TABLE: `host`, `guests`), `store.go` (чтение/запись участников), `handlers.go` + `web/index.html` (карточка, API), тесты `scanner_test.go`/`handlers_test.go`/`store_test.go`.
- БД: аддитивная миграция, данные не теряются, рескан заполняет новые колонки.
- Контент: ручной проход автора по 49 `episode.yaml` на CT вне кода сервиса (README — инструкция и рецепт прогресса).
- Документация: README (схема meta, раздел про участников).
