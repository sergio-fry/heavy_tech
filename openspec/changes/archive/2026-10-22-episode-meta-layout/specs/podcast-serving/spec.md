# Spec Delta: podcast-serving

## ADDED Requirements

### Requirement: Видео-фид публикует выпуски с видео

`GET /feed-video.xml` MUST возвращать валидный RSS 2.0 с iTunes-расширением с теми метаданными канала из `podcast.yaml`, что и аудио-фид; элементы — эпизоды, у которых есть видеоноситель, новые сверху. У каждого элемента enclosure указывает на видеоноситель (`/video/{номер}`), guid равен enclosure URL, `itunes:episode` равен номеру эпизода. Эпизоды без видео в этом фиде MUST отсутствовать. Все URL абсолютные.

#### Scenario: Эпизод с видео в видео-фиде

- **WHEN** эпизод 7 имеет аудио- и видеоносители, запрошен `GET /feed-video.xml`
- **THEN** XML валиден, item содержит enclosure на `https://<host>/video/7` с точным размером и видео-MIME, guid равен enclosure URL, `itunes:episode` = 7

#### Scenario: Аудио-выпуск не попадает в видео-фид

- **WHEN** эпизод 5 имеет только аудионоситель, запрошен `GET /feed-video.xml`
- **THEN** item для эпизода 5 в фиде отсутствует

### Requirement: Видео стримится с поддержкой Range

`GET /video/{номер}` MUST отдавать содержимое видеоносителя эпизода с корректным Content-Type (по расширению файла) и полной поддержкой HTTP Range. Для неизвестного номера или эпизода без видео MUST возвращаться 404.

#### Scenario: Полная отдача видео

- **WHEN** эпизод 7 имеет видеоноситель `efir.mp4`, запрошен `GET /video/7` без Range
- **THEN** ответ 200 с полным содержимым файла и видео Content-Type

#### Scenario: Видео отсутствует

- **WHEN** запрошен `GET /video/5`, где эпизод 5 имеет только аудио
- **THEN** ответ 404

## MODIFIED Requirements

### Requirement: RSS-фид совместим с подкаст-приложениями

`GET /feed.xml` MUST возвращать валидный RSS 2.0 с iTunes-расширением: метаданные канала из `podcast.yaml`; элементы — эпизоды с аудионосителем, новые сверху (по `published_at`); у каждого элемента enclosure на аудионоситель `/audio/{номер}` с точным размером в байтах и MIME-типом по расширению файла, guid равен enclosure URL, `pubDate` в RFC 1123, `itunes:duration`, когда длительность известна, `itunes:episode` равен номеру. Все URL в фиде MUST быть абсолютными.

#### Scenario: Фид отдаёт эпизоды в правильном порядке и с корректным enclosure

- **WHEN** в индексе есть эпизоды 3 (2026-10-01) и 7 (2026-10-15), запрошен `GET /feed.xml`
- **THEN** XML валиден, первый item — эпизод 7, у каждого item enclosure с URL `https://<host>/audio/{номер}`, точным размером, типом по расширению, guid равен enclosure URL, `itunes:episode` равен номеру

#### Scenario: Пустой канал тоже валиден

- **WHEN** в папке нет эпизодов, запрошен `GET /feed.xml`
- **THEN** возвращается валидный RSS с метаданными канала и без items

#### Scenario: Эпизод в AAC получает MIME по формату файла

- **WHEN** эпизод 4 имеет аудио `.aac` (MIME `audio/aac`), эпизод 5 — `.m4a` (MIME `audio/x-m4a`), запрошен `GET /feed.xml`
- **THEN** enclosure эпизода 4 имеет тип `audio/aac`, эпизода 5 — `audio/x-m4a`

### Requirement: Аудио стримится с поддержкой Range

`GET /audio/{номер}` MUST отдавать содержимое аудионосителя эпизода с корректным Content-Type и полной поддержкой HTTP Range (206 Partial Content для диапазонов, устойчивость к докачкам подкаст-приложений). Content-Type MUST соответствовать MIME-типу носителя, сохранённому в индексе. Для неизвестного номера или эпизода без аудио MUST возвращаться 404.

#### Scenario: Полное скачивание

- **WHEN** эпизод 1 имеет аудио `.mp3`, запрошен `GET /audio/1` без Range
- **THEN** ответ 200 с полным содержимым файла и Content-Type `audio/mpeg`

#### Scenario: Докачка с середины

- **WHEN** запрошен `GET /audio/1` с `Range: bytes=1000-1999`
- **THEN** ответ 206 со 1000 запрошенными байтами и корректным `Content-Range`

#### Scenario: Неизвестный эпизод

- **WHEN** запрошен `GET /audio/999`
- **THEN** ответ 404

#### Scenario: Content-Type соответствует формату эпизода

- **WHEN** эпизод 4 имеет аудио `.aac`, запрошен `GET /audio/4` без Range
- **THEN** ответ 200 с Content-Type `audio/aac`; Range-запросы работают так же, как для MP3

### Requirement: Сайт показывает список эпизодов с плеером

`GET /` MUST возвращать HTML-страницу со списком эпизодов от новых к старым: номер выпуска, дата словами по-русски, заголовок, описание, суммарные счётчики скачиваний (аудио + видео) и прослушиваний, встроенный аудиоплеер для эпизодов с аудио и явные ссылки «скачать» на каждый доступный носитель с размером файла. Страница MUST содержать герой-блок канала: название, описание и обложку из `podcast.yaml` (когда обложка задана), действие «слушать последний выпуск» (запускает воспроизведение самого нового эпизода с аудио) и действие «скопировать ссылку на RSS». Плеер эпизода MUST иметь кнопку play/pause и прогресс-бар с перемоткой по клику; при старте воспроизведения плеер отправляет `POST /track/play`. Нативный `<audio controls>` не используется. Для видео ссылки на скачивание есть, веб-плеер видео не отображается. Пустой список MUST отображаться осмысленной заглушкой.

#### Scenario: Эпизод виден на сайте

- **WHEN** в индексе есть эпизод 7 «Аким Губанов» (дата 2026-10-15, аудио и видео, 120+30 скачиваний), запрошен `GET /`
- **THEN** HTML содержит номер выпуска, дату словами, заголовок, описание, плеер с `data-episode="7"`, суммарные счётчики и ссылки «скачать» на `/audio/7` и `/video/7` с размерами

#### Scenario: Видео-выпуск без аудио

- **WHEN** эпизод 5 имеет только видеоноситель, запрошен `GET /`
- **THEN** карточка эпизода 5 содержит ссылку на скачивание видео, аудиоплеер для него не отображается

#### Scenario: Герой-блок и копирование RSS

- **WHEN** в `podcast.yaml` заданы название, описание и обложка, запрошен `GET /`
- **THEN** HTML содержит герой-блок с названием, описанием и обложкой канала, кнопку «слушать последний выпуск» с номером самого нового эпизода с аудио и элемент копирования RSS-ссылки (абсолютный URL `/feed.xml`)

#### Scenario: Пустой подкаст

- **WHEN** эпизодов нет, запрошен `GET /`
- **THEN** страница отображает заглушку «Выпуски скоро появятся» и ссылку на фид

### Requirement: JSON API отдаёт машинный список эпизодов

`GET /api/episodes` MUST возвращать JSON-массив эпизодов от новых к старым с полями: номер, заголовок, описание, дата публикации, доступные носители (kind, абсолютный URL, размер в байтах, длительность), счётчики скачиваний раздельно по audio и video и их сумма, счётчик прослушиваний.

#### Scenario: Программный доступ к списку

- **WHEN** запрошен `GET /api/episodes`
- **THEN** ответ 200, Content-Type `application/json`, массив упорядочен от нового к старому, каждый элемент содержит перечисленные поля, включая разбивку скачиваний по носителям и сумму

### Requirement: Публичная поверхность доступна без авторизации

Фиды, аудио, видео, сайт и JSON API MUST быть доступны без аутентификации; единственная защищаемая точка — рескан, и тот может оставаться публичным (операция идемпотентна и безопасна). Ограничение доступа при необходимости решается на обратном прокси, вне кода сервиса.

#### Scenario: Всё публично

- **WHEN** анонимный клиент запрашивает `/`, `/feed.xml`, `/feed-video.xml`, `/api/episodes`, `/audio/{n}`, `/video/{n}`
- **THEN** все ответы успешны без каких-либо заголовков аутентификации
