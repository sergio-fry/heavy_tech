# Proposal

## Why

Идентичность эпизода сейчас выведена из имени файла (`YYYY-MM-DD-slug.mp3`), носитель ровно один, а несколько форматов у одного выпуска — ошибка синхронизации. Практика уже сломала эту модель: выпуски копируются в AAC, а video-версий выпусков нет вовсе, хотя формат подкаста предполагает видео. Расширять filename-конвенцию дальше нельзя — она не выражает «один выпуск, несколько носителей».

## What Changes

- **Папка = эпизод = номер.** Вместо плоских файлов — папки с числовыми именами (`1`, `2`, …, `^[1-9][0-9]*$`, без ведущих нулей). Номер заменяет slug во всех URL, guid'ах и индексе: `/audio/7`, `/video/7`. **BREAKING**: все существующие guid (`/audio/{slug}`) умирают; подписчики увидят выпуски как новые. Принято осознанно: статистика и стабильность подписок пока не критичны.
- **`episode.yaml` обязателен** в каждой папке эпизода: `title`, `published_at`, секции `audio:`/`video:` со ссылкой на файл и характеристиками (duration, bitrate, resolution — информационные, сканер не валидирует). Sidecar `slug.yaml` и конвенция имени файла упраздняются. Имена media-файлов свободные.
- **Ровно 0..1 audio + 0..1 video на эпизод.** Классификация по расширению: audio = `mp3, aac, m4a`, video = `mp4, mov, mkv, webm`. Файл в папке, не упомянутый в meta, — ошибка синхронизации; dot-файлы (scp-временки) игнорируются.
- **Два фида**: `/feed.xml` — эпизоды с аудио (guid = `/audio/{n}`), `/feed-video.xml` — эпизоды с видео (guid = `/video/{n}`). `itunes:episode` = номер.
- **Счётчики раздельно по audio/video** (`download_events` получает измерение kind), в UI и API — сумма плюс разбивка.
- **Скачивание в UI**: явные ссылки на каждый доступный носитель с размером; видео — только скачивание (веб-плеер для видео не входит в объём).
- **Миграция одноразовым скриптом на сервере**: плоские `.m4a` (mp3 уже удалены из эксплуатации) сворачиваются в папки-номера хронологически (1 = старейший), meta генерируется, характеристики заполняет `ffprobe`. База начинается с нуля (старая убирается в sidecar).

Допущения, зафиксированные в ходе проработки: сортировка фида/сайта — по `published_at` из meta; номер после публикации неизменяем (переименование папки = удаление и новый выпуск); meta без единого media-файла — ошибка; содержимое характеристик сканер не проверяет — только существование файлов, на которые они ссылаются.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `episode-publishing`: обнаружение эпизода по имени файла заменяется обнаружением папки-номера с обязательным `episode.yaml`; требование sidecar заменяется требованием meta с media-секциями; «слаг неизменяем» → «номер неизменяем».
- `podcast-serving`: URL аудио переходят на `/audio/{n}`; добавляется видеостриминг `/video/{n}` и видео-фид; сайт получает ссылки на скачивание и суммы счётчиков; API переходит на номера и разбивку счётчиков.
- `audience-metrics`: скачивания считаются per-kind (audio/video) с дедупликацией на комбинацию (эпизод, kind, IP, UA, сутки); бикон прослушиваний остаётся аудио-игоньским.

## Impact

- Код: `scanner.go` (обход папок, разбор и валидация meta), `store.go` + новая миграция SQL (номер как ключ, таблица носителей, kind в событиях), `handlers.go` (роуты `/audio/{n}`, `/video/{n}`, второй фид), `feed.go` (два фида, itunes:episode, guid на носитель), `web/index.html` (номера, скачивания, суммы), `config.go` (тексты флагов).
- Скрипты: новый `scripts/migrate-to-numbers.sh` (конвертация папки + ffprobe), обновление `scripts/smoke.sh` под новый layout.
- БД: миграция схемы; контентные данные стартуют с нуля (решение зафиксировано).
- Спеки: все три существующие capability переписываются частично; обратной совместимости URL/guid нет (BREAKING).
- Документация: README (конвенции папок, миграция, эксплуатация), инфра-репо деплоится отдельным шагом (bump ref в роли heavytech) — вне этого репозитория.
- Тесты: `scanner_test.go`, `handlers_test.go`, `store_test.go` переписываются под папки/meta/номера; фикстуры — synthetic-файлы, валидность аудио не проверяется.
