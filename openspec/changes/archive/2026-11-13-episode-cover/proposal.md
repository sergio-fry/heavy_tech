# Proposal

## Why

У выпусков нет обложки: страница выпуска и списки выглядят текстом без картинки, а в карточках и архиве нечем «встретить глаз». Обложка — стандартная часть подкаст-выпуска: она украшает страницу выпуска, даёт миниатюру в списках и попадает в превью при расшаривании. Сейчас есть только канальная обложка (`image` в `podcast.yaml`) — она одна на весь сайт.

## What Changes

- В `episode.yaml` появляется опциональное поле `cover` — имя файла-картинки в той же папке эпизода (`oblozhka.jpg`). Поддерживаются расширения `.jpg`/`.jpeg`/`.png`/`.webp`. Поле необязательно: нет — выпуск публикуется как раньше, без обложки.
- Валидация как у остальных файлов meta: файл обязан существовать в папке эпизода, быть обычным файлом и иметь поддерживаемое расширение; значение — только строка; обложка помечается «упомянутой», и лишним файлом больше не считается.
- Индекс хранит путь к обложке (`episodes.cover`), сайт получает: большую обложку на странице выпуска (и `og:image`, и artwork в Media Session — через существующий `data-cover`), маленькую миниатюру в архиве и на карточках лендинга, поле `cover` (абсолютный URL) в `/api/episodes`, `image` в JSON-LD выпуска.
- Обложки раздаются по стабильному именованному URL `/cover/{номер}/{NNN-slug.ext}` (и короткому `/cover/{номер}`) без счётчика скачиваний: обложка — оформление, а не носитель.

Допущения: обложка квадратная картинка (обычно 1:1), но соотношение не проверяется — браузер обрезает через `object-fit: cover`; замена файла картинки с тем же именем подхватывается отдачей без изменения индекса (Last-Modified берётся с диска при каждом запросе); фиды (`feed.xml`) не меняются — per-item `itunes:image` не входило в запрос.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `episode-publishing`: новое требование — meta может описывать обложку выпуска (`cover`: имя файла-картинки в папке эпизода), строгая валидация типа и файла.
- `podcast-serving`: страница выпуска показывает обложку (и отдаёт её как `og:image`), архив и карточки — миниатюры, JSON API — поле `cover`, JSON-LD — `image`, новый маршрут `/cover/{номер}`.

## Impact

- Код: `scanner.go` (разбор `cover`, валидация), миграция `migrations/0006_episode_cover.sql` (ALTER TABLE: `cover`), `store.go` (чтение/запись/сравнение), `slug.go`+`links.go` (именованный URL обложки), `handlers.go` (маршруты `/cover/…`, поле API), `pages.go` (поля элемента, `og:image` выпуска), `seo.go` (JSON-LD `image`), шаблоны `web/` (страница выпуска, карточка, архив) и `web/style.css`.
- БД: аддитивная миграция, данные не теряются; рескан заполняет колонку.
- Контент: ручной шаг автора — положить картинку в папку выпуска и добавить `cover:` в `episode.yaml` (README — инструкция).
- Документация: README (схема meta, раздел «Обложка выпуска»).
