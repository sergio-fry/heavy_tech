# Proposal

## Why

Сейчас сервис принимает только `.mp3`: сканер игнорирует файлы с другими расширениями, а mime жёстко задан как `audio/mpeg`. Записи в AAC (телефоны, диктофоны, студия Tributary при соответствующей настройке экспорта) приходится вручную перекодировать в MP3 перед публикацией. Поддержка AAC убирает этот ручной шаг: положил файл в папку — выпустил.

## What Changes

- Сканер распознаёт аудиофайлы эпизодов с расширениями `.mp3`, `.aac` и `.m4a` по той же конвенции имени `YYYY-MM-DD-slug.mp3` (дата и слаг — без изменений).
- MIME-тип эпизода выводится из расширения: `.mp3` → `audio/mpeg`, `.aac` → `audio/aac`, `.m4a` → `audio/x-m4a`. Значение сохраняется в индексе (колонка `mime` уже существует, миграция не нужна) и автоматически попадает в enclosure фида и в `Content-Type` отдачи аудио.
- Дубликат слага у файлов с разными расширениями (например, `x.mp3` и `x.m4a`) — ошибка синхронизации, как и сегодня для одинаковых расширений.
- Остальная семантика без изменений: guid = URL `/audio/{slug}` (от расширения не зависит), оценка длительности по размеру — прежняя (128 kbps, sidecar `duration` перекрывает), слаг неизменяем после публикации.
- README и справка флага `-podcast-dir` обновляются под мультиформат.

Допущение (записано для проверки при ревью): «поддержка AAC» трактуется расширительно — и сырой ADTS-поток `.aac`, и AAC в MP4-контейнере `.m4a`, поскольку оба формата встречаются на практике, а дополнительная сложность — одна строка в карте расширений.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `episode-publishing`: требование обнаружения эпизода по имени файла — расширение перестаёт быть только `.mp3`, добавляется карта «расширение → MIME» и сценарий дубликата слага между форматами.
- `podcast-serving`: к требованиям фида и стриминга добавляются сценарии для эпизодов в AAC — enclosure фида несёт MIME по расширению, `GET /audio/{slug}` отдаёт соответствующий Content-Type.

## Impact

- Код: `scanner.go` (регулярное выражение имени и жёсткий mime), `handlers.go` (жёсткое имя `episode.mp3` в `ServeContent` — заменить на фактическое имя файла; Content-Type уже берётся из индекса), тесты `scanner_test.go`, `handlers_test.go`.
- БД: миграций нет — колонка `mime` в `episodes` уже есть и заполняется сканером.
- Фид/сайт/API: изменений кода не требуют — везде читают `Mime` из индекса; контракты дополняются только сценариями для AAC.
- Фикстуры: добавить тестовые файлы `.aac`/`.m4a` (содержимое не важно — сканер и отдача читают только метаданные файла, валидность аудио не проверяется).
- Документация: README.md, текст флага `-podcast-dir` в `config.go`.
