# Proposal

## Why

Ссылки на носители сейчас без имени файла — `https://heavytech.udalovs.ru/video/1`. Браузер и подкаст-приложения сохраняют такой файл как `1` без расширения, из-за чего он не открывается двойным кликом, а получателю непонятно, что это за выпуск. Имя файла на диске при этом менять не нужно: это вопрос публичного URL.

## What Changes

- **Канонический URL носителя содержит имя файла:** `/{audio|video}/{номер}/{номер}-{slug}.{ext}`, например `https://heavytech.udalovs.ru/video/39/039-vse-flomastery-raznye.mp4`.
  - Номер в имени дополняется нулями до трёх цифр (`039`, `1000` остаётся `1000`).
  - Slug — транслит заголовка выпуска в нижний регистр (`Все фломастеры разные` → `vse-flomastery-raznye`), обрезка по границе слова до 60 символов; если транслит пуст — имя без slug (`039.mp4`).
  - Расширение — реальное расширение файла из индекса (`.m4a`, `.mp3`, `.aac`, `.mp4`, …).
- **Один URL на стриминг и скачивание.** Плеер, кнопка «скачать» и enclosure используют канонический именованный URL. `Content-Disposition: attachment` не нужен: имя уже в пути, а ссылка «скачать» сохраняет файл под именем из URL благодаря атрибуту `download`. Следствие: имя файла при скачивании совпадает с именем в ссылке.
- **Стабильные URL-идентификаторы сохраняются.** `/audio/{номер}` и `/video/{номер}` продолжают отдавать тот же носитель (это guid в фидах и старые ссылки); имя в третьем сегменте — декоративное, поиск идёт по номеру, поэтому смена заголовка не ломает ранее опубликованные ссылки.
- **Фиды:** `enclosure` переходит на именованный URL, `guid` остаётся прежним `/audio/{номер}` / `/video/{номер}` — подписчики не увидят выпуски как новые. **Не BREAKING** для guid, но enclosure-URL меняется (приложения один раз перекачают файл по новому адресу при необходимости).
- **Сайт:** ссылки «скачать» ведут на именованный URL с атрибутом `download`; `<audio src>` использует тот же именованный URL.
- **API:** `media[].url` отдаёт канонический именованный URL.
- **Диск не меняется:** имена файлов в папке эпизода остаются прежними, slug вычисляется из заголовка при построении ссылок.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `podcast-serving`: медиа-URL получает имя файла (`/{kind}/{номер}/{номер}-{slug}.{ext}`) для стриминга и скачивания; `enclosure` фидов переходит на именованный URL при неизменном `guid`; сайт и API публикуют именованные ссылки.
- `audience-metrics`: формулировка учитываемых запросов расширяется на именованные варианты медиа-URL (поведение учёта не меняется).

## Impact

- Код: `handlers.go` (маршруты `/{kind}/{number}/{name}`, построение `mediaURL`, API `media.url`), `feed.go` (enclosure — именованный URL, guid — номерной), `web/index.html` (`<audio src>` и ссылки скачивания уже берут URL из данных, правок разметки минимум), новый хелпер транслитерации/slug (например, `slug.go`).
- БД: изменений схемы нет — slug детерминированно вычисляется из `title` и расширения файла, уже хранящихся в индексе.
- Спеки: `podcast-serving` и `audience-metrics`; `episode-publishing` и конвенция папок не меняются.
- Совместимость: guid и номерные маршруты стабильны; старые именованные ссылки после смены заголовка продолжают работать (имя сегмента игнорируется при поиске).
- Тесты: `handlers_test.go` (новые URL, 200 по номерному и именованному маршруту, `download`-атрибут, API, фиды), новый тест slug/транслита; `scripts/smoke.sh` — проверка имени в ссылке.
- Документация: README — форма медиа-URL, правило имени файла, неизменность guid.
