# Spec Delta: podcast-serving

## ADDED Requirements

### Requirement: Markdown-описание рендерится в безопасный HTML

Описание выпуска (из `description.md` или из поля meta) MUST интерпретироваться как markdown и MUST выводиться HTML-разметкой: абзацы, переносы строк, списки, выделение, ссылки. Сырой HTML из исходника MUST не исполняться: активная разметка (скрипты, обработчики, произвольные теги) MUST быть экранирована или отброшена. Пустое или частично некорректное markdown-описание MUST не ломать страницу и не давать ошибку.

#### Scenario: Форматирование превращается в разметку

- **WHEN** описание эпизода 7 содержит `**важно**`, список из двух пунктов и ссылку `[гость](https://example.com)`, запрошен `GET /`
- **THEN** HTML карточки содержит `<strong>важно</strong>`, элементы списка и ссылку с адресом `https://example.com`

#### Scenario: Сырой HTML не исполняется

- **WHEN** описание содержит `<script>alert(1)</script>` и `<img src=x onerror=alert(1)>`
- **THEN** HTML страницы не содержит исполняемого тега `script` и атрибута-обработчика `onerror` из описания

#### Scenario: Пустое описание не ломает страницу

- **WHEN** у эпизода описания нет, запрошен `GET /`
- **THEN** страница отдаётся успешно, карточка эпизода выводится без блока описания

## MODIFIED Requirements

### Requirement: RSS-фид совместим с подкаст-приложениями

`GET /feed.xml` MUST возвращать валидный RSS 2.0 с iTunes-расширением: метаданные канала из `podcast.yaml`; элементы — эпизоды с аудионосителем, новые сверху (по `published_at`); у каждого элемента enclosure на аудионоситель `/audio/{номер}` с точным размером в байтах и MIME-типом по расширению файла, guid равен enclosure URL, `pubDate` в RFC 1123, `itunes:duration`, когда длительность известна, `itunes:episode` равен номеру, а `description` содержит HTML, отрендеренный из markdown-описания эпизода и корректно экранированный в XML. Все URL в фиде MUST быть абсолютными.

#### Scenario: Фид отдаёт эпизоды в правильном порядке и с корректным enclosure

- **WHEN** в индексе есть эпизоды 3 (2026-10-01) и 7 (2026-10-15), запрошен `GET /feed.xml`
- **THEN** XML валиден, первый item — эпизод 7, у каждого item enclosure с URL `https://<host>/audio/{номер}`, точным размером, типом по расширению, guid равен enclosure URL, `itunes:episode` равен номеру

#### Scenario: Описание в фиде — отрендеренный markdown

- **WHEN** описание эпизода 7 содержит markdown-разметку (выделение, ссылка), запрошен `GET /feed.xml`
- **THEN** XML валиден, `description` item'а после XML-разбора содержит HTML-теги (`<p>`, `<strong>`, `<a>`), исходная markdown-разметка в description не выводится

#### Scenario: Пустой канал тоже валиден

- **WHEN** в папке нет эпизодов, запрошен `GET /feed.xml`
- **THEN** возвращается валидный RSS с метаданными канала и без items

#### Scenario: Эпизод в AAC получает MIME по формату файла

- **WHEN** эпизод 4 имеет аудио `.aac` (MIME `audio/aac`), эпизод 5 — `.m4a` (MIME `audio/x-m4a`), запрошен `GET /feed.xml`
- **THEN** enclosure эпизода 4 имеет тип `audio/aac`, эпизода 5 — `audio/x-m4a`

### Requirement: Сайт показывает список эпизодов с плеером

`GET /` MUST возвращать HTML-страницу со списком эпизодов от новых к старым: номер выпуска, дата словами по-русски, заголовок, отрендеренное markdown-описание, единый счётчик потребления выпуска (сумма скачиваний аудио и видео и прослушиваний), встроенный аудиоплеер для эпизодов с аудио и явные ссылки «скачать» на каждый доступный носитель с размером файла. Если у эпизода задана YouTube-ссылка, карточка MUST содержать действие «Смотреть на YouTube» с этой ссылкой; при отсутствии ссылки действия нет. Страница MUST содержать герой-блок канала: название, описание и обложку из `podcast.yaml` (когда обложка задана), действие «слушать последний выпуск» (запускает воспроизведение самого нового эпизода с аудио) и действие «скопировать ссылку на RSS». Плеер эпизода MUST иметь кнопку play/pause и прогресс-бар с перемоткой по клику; при старте воспроизведения плеер отправляет `POST /track/play`. Нативный `<audio controls>` не используется. Для видео ссылки на скачивание есть, веб-плеер видео не отображается. Пустой список MUST отображаться осмысленной заглушкой.

#### Scenario: Эпизод виден на сайте

- **WHEN** в индексе есть эпизод 7 «Аким Губанов» (дата 2026-10-15, аудио и видео, 120 скачиваний аудио, 30 видео, 5 прослушиваний), запрошен `GET /`
- **THEN** HTML содержит номер выпуска, дату словами, заголовок, отрендеренное описание, плеер с `data-episode="7"`, ссылки «скачать» на `/audio/7` и `/video/7` с размерами и единый счётчик со значением 155

#### Scenario: YouTube-ссылка выводится в карточке

- **WHEN** у эпизода 7 в meta задана YouTube-ссылка, запрошен `GET /`
- **THEN** карточка эпизода 7 содержит действие «Смотреть на YouTube» с этой ссылкой

#### Scenario: Без YouTube-ссылки действия нет

- **WHEN** у эпизода 7 нет YouTube-ссылки, запрошен `GET /`
- **THEN** карточка эпизода 7 не содержит действия «Смотреть на YouTube»

#### Scenario: Видео-выпуск без аудио

- **WHEN** эпизод 5 имеет только видеоноситель, запрошен `GET /`
- **THEN** карточка эпизода 5 содержит ссылку на скачивание видео, аудиоплеер для него не отображается

#### Scenario: Герой-блок и копирование RSS

- **WHEN** в `podcast.yaml` заданы название, описание и обложка, запрошен `GET /`
- **THEN** HTML содержит герой-блок с названием, описанием и обложкой канала, кнопку «слушать последний выпуск» с номером самого нового эпизода с аудио и элемент копирования RSS-ссылки (абсолютный URL `/feed.xml`)

#### Scenario: Пустой подкаст

- **WHEN** эпизодов нет, запрошен `GET /`
- **THEN** страница отображает заглушку «Выпуски скоро появятся» и ссылку на фид

### Requirement: JSON API отдаёт машинный список эпизодов

`GET /api/episodes` MUST возвращать JSON-массив эпизодов от новых к старым с полями: номер, заголовок, описание как markdown-исходник, дата публикации, ссылка на YouTube (пустая строка, когда не задана), доступные носители (kind, абсолютный URL, размер в байтах, длительность), счётчики скачиваний раздельно по audio и video и их сумма, счётчик прослушиваний.

#### Scenario: Программный доступ к списку

- **WHEN** запрошен `GET /api/episodes`
- **THEN** ответ 200, Content-Type `application/json`, массив упорядочен от нового к старому, каждый элемент содержит перечисленные поля, включая разбивку скачиваний по носителям, сумму и ссылку на YouTube

#### Scenario: YouTube-ссылка в API

- **WHEN** у эпизода 7 задана YouTube-ссылка, у эпизода 6 — нет, запрошен `GET /api/episodes`
- **THEN** у элемента 7 поле `youtube` содержит заданный URL, у элемента 6 — пустую строку

#### Scenario: Описание в API остаётся markdown-исходником

- **WHEN** описание эпизода 7 содержит `**важно**`, запрошен `GET /api/episodes`
- **THEN** поле `description` содержит исходный markdown-текст, HTML-разметка в нём не выводится
