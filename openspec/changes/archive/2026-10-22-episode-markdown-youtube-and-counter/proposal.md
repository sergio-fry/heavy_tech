# Proposal

## Why

Описание выпуска сейчас — однострочное поле `description` в `episode.yaml`, и на сайте оно выводится как один абзац: ссылки, списки и выделение из шоу-ноутов теряются, а длинные тексты читаются плохо. Кроме того, у выпуска нет ссылки на видеоверсию на YouTube. Счётчики скачиваний и прослушиваний показываются двумя цифрами, хотя для читателя это одна величина «сколько раз выпуск потребляли».

## What Changes

- **Описание выпуска хранится в markdown-файле.** В папке эпизода появляется необязательный `description.md`; его содержимое — источник описания и рендерится в HTML на сайте и в фидах (ссылки, списки, выделение, переносы строк). Файл `description.md` имеет приоритет над legacy-полем `description:` в `episode.yaml`; поле остаётся фолбэком (интерпретируется как markdown) для существующих 49 выпусков, миграция данных не требуется.
- **Markdown рендерится безопасно.** Сырой HTML из markdown не исполняется (экранируется/отбрасывается), так что автор файла не может случайно внести XSS.
- **Ссылка на YouTube-выпуск.** Новое необязательное поле `youtube:` в `episode.yaml` (абсолютный `http(s)` URL). На сайте — действие «Смотреть на YouTube» в карточке эпизода; в JSON API — поле `youtube`. В RSS-фиды ссылка не добавляется (идентичность item остаётся за enclosure/guid).
- **Счётчик потребления на сайте — одна цифра.** Сайт показывает суммарное «Скачиваний и прослушиваний: N» = скачивания (аудио + видео) + прослушивания. Метрики продолжают собираться и храниться раздельно; JSON API сохраняет разбивку `downloads{audio,video,total}` и `plays`.
- **Видео-скачивание: изменений не требуется.** Ссылки «Скачать Видео» уже выводятся для эпизодов с локальным видеоносителем; на проде их не видно только потому, что видео-версий ещё не загружено. Поведение фиксируется как существующее (без правок кода), с проверкой в тестах.

Допущения, зафиксированные при уточнении: markdown нужен для описания выпуска (не канала); YouTube-ссылка — на выпуск целиком (одна на эпизод), только сайт и API; объединение счётчиков — только отображение на сайте, сбор и API — раздельно.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `episode-publishing`: в конвенцию папки-эпизода добавляется необязательный `description.md` (приоритетный источник описания) и необязательное поле `youtube:` с валидацией URL; правило «неупомянутый файл — ошибка» учитывает `description.md`.
- `podcast-serving`: сайт рендерит markdown-описание в HTML, показывает ссылку на YouTube и единый счётчик потребления; RSS-описание становится HTML из markdown; API получает поле `youtube` (описание остаётся markdown-исходником).
- `audience-metrics`: требование «Счётчики видны на сайте и в API» меняется — сайт показывает одну суммарную цифру (скачивания + прослушивания), API сохраняет раздельные агрегаты.

## Impact

- Код: `scanner.go` (чтение `description.md`, поле `youtube`, валидация), `store.go` + миграция `0003_*.sql` (колонка `youtube` в `episodes`), новый `markdown.go` (рендер goldmark), `handlers.go` (рендер HTML для сайта/фида, `youtube` в API, единый счётчик), `feed.go` (HTML-описание), `web/index.html` (HTML-описание, кнопка YouTube, один счётчик).
- Зависимости: `github.com/yuin/goldmark` (новая, чистый Go, без cgo).
- Данные: схема SQLite расширяется неразрушающей миграцией (ADD COLUMN с дефолтом); существующие эпизоды не переписываются, `description` из YAML продолжает работать.
- Спеки: три существующие capability обновляются частично; обратной несовместимости URL/guid нет.
- Документация: README — конвенция `description.md`, поле `youtube`, семантика объединённого счётчика.
- Тесты: `scanner_test.go`, `store_test.go`, `handlers_test.go`, новые тесты рендера markdown и деградации legacy-описания.
