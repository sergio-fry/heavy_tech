# Spec Delta: audience-metrics

## Purpose

Счёт «любопытственного» уровня: сколько эпизод скачивают и сколько прослушивают в браузере — без претензии на IAB-сертификацию, но устойчиво к типичным искажениям (Range-докачки, боты).

## ADDED Requirements

### Requirement: Скачивание считается один раз на клиента в сутки

Система MUST засчитывать скачивание эпизода при успешном `GET /audio/{slug}` не-HEAD-запросом и не более одного раза в сутки (UTC) на комбинацию (эпизод, хеш IP, хеш User-Agent). Повторные запросы той же комбинации в те же сутки, включая Range-продолжения той же докачки, MUST увеличивать счётчик только на первом запросе.

#### Scenario: Докачка не раздувает счётчик

- **WHEN** один клиент в течение дня запрашивает эпизод тремя Range-запросами
- **THEN** счётчик скачиваний эпизода вырос ровно на 1

#### Scenario: Новые сутки — новое скачивание

- **WHEN** тот же клиент запрашивает тот же эпизод на следующие сутки
- **THEN** счётчик вырос ещё на 1

### Requirement: Ботовые и HEAD-запросы не считаются

Запросы методом HEAD и запросы с User-Agent, похожим на краулер/монитор (шаблоны `bot`, `spider`, `crawler`, `monitor`), MUST не засчитываться как скачивания. Запросы без User-Agent MUST также не засчитываться.

#### Scenario: Проверка доступности не считается

- **WHEN** мониторинг делает `HEAD /audio/{slug}` каждый час
- **THEN** счётчик скачиваний не изменился

#### Scenario: Краулер не считается

- **WHEN** запрошен `GET /audio/{slug}` с User-Agent `SomeBot/1.0`
- **THEN** счётчик скачиваний не изменился

### Requirement: Прослушивание фиксируется биконом плеера

Веб-плеер на сайте MUST отправлять `POST /track/play` при старте воспроизведения эпизода; система MUST записывать событие прослушивания с опциональным процентом прогресса. Для неизвестного слага MUST возвращаться 4xx и событие не записывается. Повторные биконы одного эпизода в сутки от одного браузера не обязательны к дедупликации.

#### Scenario: Клик по play увеличил счётчик

- **WHEN** посетитель нажал play у эпизода `pervyy-vypusk`, плеер отправил `POST /track/play` с этим слагом
- **THEN** событие прослушивания записано, счётчик прослушиваний эпизода вырос на 1

#### Scenario: Бикон по неизвестному эпизоду отброшен

- **WHEN** отправлен `POST /track/play` со slug `net-takogo`
- **THEN** ответ 4xx, событие не записано

### Requirement: Счётчики видны на сайте и в API

Сайт и JSON API MUST показывать по каждому эпизоду суммарные скачивания и прослушивания за всё время. Агрегаты MUST вычисляться из сырых событий запросами, без предвычисленных счётчиков в индексе эпизодов.

#### Scenario: Числа согласованы

- **WHEN** у эпизода 3 скачивания и 1 прослушивание, запрошены `GET /` и `GET /api/episodes`
- **THEN** оба представления показывают downloads=3, plays=1

### Requirement: Сырые IP и User-Agent не хранятся

Система MUST хранить в событиях только сольтированные хеши IP и User-Agent; сырые значения MUST не записываться ни в SQLite, ни в логи приложения.

#### Scenario: В базе нет персональных данных

- **WHEN** зафиксированы скачивания и прослушивания, выполнен осмотр таблиц событий
- **THEN** ни в одной строке нет сырого IP или полного User-Agent, только хеши
