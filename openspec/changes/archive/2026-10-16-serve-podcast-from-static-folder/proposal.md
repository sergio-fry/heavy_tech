# Proposal: serve-podcast-from-static-folder

## Why

Готовые выпуски подкаста записываются в Tributary (record.udalovs.ru), но публиковать их некуда: нужен простой сервис, который раздаёт аудио из статичной папки, отдаёт RSS-фид для подкаст-приложений, показывает сайт со списком эпизодов и плеером и собирает метрики скачиваний/прослушиваний. Отдельно поднимать CMS или использовать сторонние хостинги не хочется — управление должно происходить через файлы в папке.

## What Changes

- Новый greenfield-сервис на Go (один бинарник): веб-сервер с публичным API и сайтом.
- Управление контентом через файлы: папка `data/podcast/` — источник истины. Эпизод добавляется копированием MP3 (имя `YYYY-MM-DD-slug.mp3`), опциональный sidecar `.yaml` уточняет заголовок/описание, `podcast.yaml` в корне описывает канал.
- Сканер при старте и по запросу (`POST /admin/rescan`) сверяет папку с SQLite: таблица эпизодов — производный индекс.
- Публичная поверхность:
  - `GET /` — HTML-страница: список эпизодов с датами, описаниями, счётчиками и `<audio>`-плеером;
  - `GET /feed.xml` — RSS 2.0 с iTunes-тегами (enclosure с точным размером, стабильный guid, длительность);
  - `GET /audio/{slug}` — стриминг аудио с поддержкой Range (совместим с подкаст-приложениями), запрос считается скачиванием;
  - `POST /track/play` — бикон старта воспроизведения из веб-плеера (прослушивание);
  - `GET /api/episodes` — JSON-список эпизодов для программного доступа.
- Метрики «любопытственного» уровня в SQLite: скачивание = уникальный (эпизод, hash IP, hash UA, сутки) с игнорированием HEAD и ботов; прослушивания пишутся сырыми событиями; агрегаты считаются запросами.
- Всё публично, без авторизации (хобби-проект; при необходимости basic auth добавляется на edge-Caddy без изменений кода).
- Один подкаст на инстанс: без сущности «шоу» в схеме.

## Capabilities

### New Capabilities

- `episode-publishing`: файловое управление эпизодами — конвенции имён, sidecar-метадата, конфиг канала, синхронизация папки с индексом SQLite.
- `podcast-serving`: публичная раздача — RSS-фид с iTunes-тегами, стриминг аудио с Range, HTML-сайт со списком и плеером, JSON API.
- `audience-metrics`: подсчёт скачиваний и прослушиваний — правила дедупликации, приём биконов, отображение счётчиков на сайте.

## Impact

- Новый код: весь репозиторий (пуст на момент старта). Ориентир стека — как в profilerpro: Go 1.26, `modernc.org/sqlite` (pure Go), миграции goose, stdlib `net/http` (роутинг 1.22+), `html/template`, рукописный фид на `encoding/xml`.
- Артефакт деплоя: бинарник + SQLite-файл + статичная папка; systemd-юнит позже, вне этого репо (по конвенциям infra: LXC, edge-Caddy, отдельный слот — CT 132 занят Tributary).
- Внешние контракты: фид и аудио-URL должны быть абсолютными и публичными; смена слага эпизода ломает guid — имена файлов после публикации считать неизменяемыми.
- Зависимости: минимум сторонних пакетов; парсинг MP3-фреймов не делаем (длительность — из sidecar либо оценка байты/битрейт).
