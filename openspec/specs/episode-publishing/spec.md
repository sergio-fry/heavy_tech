# episode-publishing Specification

## Purpose

Управление эпизодами подкаста происходит исключительно через файлы в папке: папка — источник истины, а SQLite-индекс — производное состояние, которое сервис синхронизирует при старте и по запросу.

## Requirements

### Requirement: Эпизод обнаруживается по имени файла

Система MUST распознавать аудиофайл эпизода по имени вида `YYYY-MM-DD-slug.mp3` в папке подкастов: `YYYY-MM-DD` задаёт дату публикации, `slug` — стабильный идентификатор эпизода. Файлы, не соответствующие шаблону, MUST игнорироваться. Поддерживаются как минимум расширения `.mp3` (mime `audio/mpeg`).

#### Scenario: Новый файл попадает в индекс

- **WHEN** в папку подкастов помещён файл `2026-10-01-pervyy-vypusk.mp3` и выполнен рескан
- **THEN** эпизод со slug `pervyy-vypusk` и датой публикации 2026-10-01 появляется в индексе и доступен через сайт, фид и API

#### Scenario: Файл с неверным именем игнорируется

- **WHEN** в папке лежит файл `my-episode.mp3` (без даты) и выполнен рескан
- **THEN** эпизод не создаётся, сервис продолжает работать

### Requirement: Sidecar-файл уточняет метаданные эпизода

Рядом с аудиофайлом MAY лежать sidecar-файл `<slug>.yaml`, содержащий опциональные поля: заголовок (`title`), описание (`description`), длительность в секундах (`duration`). Если sidecar существует, система MUST использовать его значения вместо производных из имени файла; если поля нет или файла нет — брать значение по умолчанию (заголовок — из слага, длительность — оценка по размеру и битрейту).

#### Scenario: Sidecar задаёт заголовок и описание

- **WHEN** для `2026-10-01-pervyy-vypusk.mp3` существует `pervyy-vypusk.yaml` с `title: «Первый выпуск»` и `description: "О чём этот подкаст"`
- **THEN** в индексе, на сайте и в фиде эпизод опубликован с этим заголовком и описанием

#### Scenario: Без sidecar заголовок выводится из слага

- **WHEN** эпизод `2026-10-01-pervyy-vypusk.mp3` не имеет sidecar-файла
- **THEN** заголовок эпизода получен из слага (слова из дефисов, первая буква заглавная), описание пустое

### Requirement: Конфигурация канала читается из podcast.yaml

В корне папки подкастов MUST читаться файл `podcast.yaml` с метаданными канала: название, ссылка, описание, автор, e-mail, обложка, категория, признак explicit. Эти значения MUST использоваться во всех публичных представлениях канала (фид, сайт). При отсутствии файла сервис MUST стартовать с ошибкой конфигурации — канал без метаданных не публикуется.

#### Scenario: Метаданные канала применяются

- **WHEN** `podcast.yaml` задаёт название и автора канала
- **THEN** фид и сайт отображают эти название и автора

#### Scenario: Нечего публиковать без конфига

- **WHEN** сервис стартует без `podcast.yaml` в папке подкастов
- **THEN** сервис завершается с понятной ошибкой конфигурации

### Requirement: Индекс синхронизируется с папкой

Система MUST при старте и по запросу `POST /admin/rescan` приводить индекс SQLite в соответствие с содержимым папки: новые файлы индексируются, исчезнувшие — удаляются из индекса (вместе с их появлением в фиде и на сайте; события метрик сохраняются). Повторный рескан без изменений в папке MUST быть идемпотентным.

#### Scenario: Рескан после добавления и удаления

- **WHEN** в папку добавлен новый MP3, а один старый удалён, и вызван `POST /admin/rescan`
- **THEN** индекс содержит новый эпизод и не содержит удалённый; повторный вызов рескана не меняет индекс

#### Scenario: Индекс восстанавливается после потери

- **WHEN** SQLite-файл удалён и сервис перезапущен
- **THEN** индекс эпизодов полностью восстановлен сканером из папки (метрики при этом начинаются с нуля)

### Requirement: Слаг после публикации неизменяем

Слаг эпизода MUST фиксироваться при первом обнаружении файла. Переименование опубликованного файла MUST трактоваться как удаление старого эпизода и добавление нового (новый guid, сброс счётчиков эпизода). В документации к сервису это поведение MUST быть явно описано.

#### Scenario: Переименование файла меняет идентичность эпизода

- **WHEN** файл `2026-10-01-a.mp3` переименован в `2026-10-01-b.mp3` и выполнен рескан
- **THEN** эпизод `a` исчез из фида и сайта, появился эпизод `b` с нулевыми счётчиками
