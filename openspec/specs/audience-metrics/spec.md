# audience-metrics Specification

## Purpose

Счёт «любопытственного» уровня: сколько эпизод скачивают и сколько прослушивают в браузере — без претензии на IAB-сертификацию, но устойчиво к типичным искажениям (Range-докачки, боты).

## Requirements

### Requirement: Скачивание считается один раз на клиента в сутки

Система MUST засчитывать скачивание носителя эпизода при успешном `GET` медиа-URL эпизода (`/audio/{номер}`, `/video/{номер}` и их именованные варианты `/{audio|video}/{номер}/{имя}.{ext}`) не-HEAD-запросом и не более одного раза в сутки (UTC) на комбинацию (эпизод, носитель, хеш IP, хеш User-Agent). Скачивания аудио и видео MUST учитываться раздельно по носителям. Повторные запросы той же комбинации в те же сутки, включая Range-продолжения той же докачки, MUST увеличивать счётчик только на первом запросе.

#### Scenario: Докачка не раздувает счётчик

- **WHEN** один клиент в течение дня запрашивает аудио эпизода 7 тремя Range-запросами
- **THEN** счётчик скачиваний аудио эпизода 7 вырос ровно на 1

#### Scenario: Аудио и видео считаются раздельно

- **WHEN** один клиент в течение дня скачал аудио и видео эпизода 7
- **THEN** счётчик аудио вырос на 1, счётчик видео вырос на 1, оба независимы

#### Scenario: Новые сутки — новое скачивание

- **WHEN** тот же клиент запрашивает тот же носитель на следующие сутки
- **THEN** счётчик вырос ещё на 1

#### Scenario: Именованный URL считается так же, как номерной

- **WHEN** один клиент в течение дня запросил аудио эпизода 7 по именованному URL `/audio/7/007-<slug>.mp3`, а затем по `/audio/7`
- **THEN** счётчик скачиваний аудио эпизода 7 вырос ровно на 1
### Requirement: Ботовые и HEAD-запросы не считаются

Запросы методом HEAD и запросы с User-Agent, похожим на краулер/монитор (шаблоны `bot`, `spider`, `crawler`, `monitor`), MUST не засчитываться как скачивания — ни аудио, ни видео. Запросы без User-Agent MUST также не засчитываться.

#### Scenario: Проверка доступности не считается

- **WHEN** мониторинг делает `HEAD /audio/7` и `HEAD /video/7` каждый час
- **THEN** счётчики скачиваний не изменились

#### Scenario: Краулер не считается

- **WHEN** запрошен `GET /audio/7` с User-Agent `SomeBot/1.0`
- **THEN** счётчик скачиваний не изменился
### Requirement: Прослушивание фиксируется биконом плеера

Веб-плеер на сайте MUST отправлять `POST /track/play` при старте воспроизведения эпизода (бикон указывает номер эпизода); система MUST записывать событие прослушивания с опциональным процентом прогресса. Для неизвестного номера MUST возвращаться 4xx и событие не записывается. Повторные биконы одного эпизода в сутки от одного браузера не обязательны к дедупликации.

#### Scenario: Клик по play увеличил счётчик

- **WHEN** посетитель нажал play у эпизода 7, плеер отправил `POST /track/play` с этим номером
- **THEN** событие прослушивания записано, счётчик прослушиваний эпизода 7 вырос на 1

#### Scenario: Бикон по неизвестному эпизоду отброшен

- **WHEN** отправлен `POST /track/play` с номером 999
- **THEN** ответ 4xx, событие не записано
### Requirement: Счётчики видны на сайте и в API

Сайт MUST показывать по каждому эпизоду единый счётчик потребления — сумму скачиваний (аудио + видео) и прослушиваний за всё время. JSON API MUST сохранять раздельные агрегаты: скачивания раздельно по audio и video и их сумму, прослушивания отдельно. Агрегаты MUST вычисляться из сырых событий запросами, без предвычисленных счётчиков в индексе эпизодов.

#### Scenario: Числа согласованы

- **WHEN** у эпизода 7 три скачивания аудио, одно видео и одно прослушивание, запрошены `GET /` и `GET /api/episodes`
- **THEN** сайт показывает единый счётчик 5, API — `downloads.audio=3`, `downloads.video=1`, `downloads.total=4`, `plays=1`

#### Scenario: Объединение не меняет раздельный сбор

- **WHEN** клиент скачал аудио эпизода 7, запрошен `GET /`
- **THEN** на сайте единый счётчик вырос на 1, в API скачивания выросли на 1, а прослушивания не изменились
### Requirement: Сырые IP и User-Agent не хранятся

Система MUST хранить в событиях только сольтированные хеши IP и User-Agent; сырые значения MUST не записываться ни в SQLite, ни в логи приложения.

#### Scenario: В базе нет персональных данных

- **WHEN** зафиксированы скачивания и прослушивания, выполнен осмотр таблиц событий
- **THEN** ни в одной строке нет сырого IP или полного User-Agent, только хеши
