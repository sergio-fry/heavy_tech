# podcast-serving Specification

## Purpose

Публичная поверхность сервиса: RSS-фид для подкаст-приложений, стриминг аудио, HTML-сайт со списком эпизодов и плеером, JSON API — всё без авторизации, с абсолютными публичными URL.

## Requirements

### Requirement: RSS-фид совместим с подкаст-приложениями

`GET /feed.xml` MUST возвращать валидный RSS 2.0 с iTunes-расширением: метаданные канала из `podcast.yaml`; элементы — опубликованные эпизоды, новые сверху; у каждого элемента enclosure с точным размером файла в байтах и корректным MIME-типом, стабильный guid (абсолютный URL аудиофайла), `pubDate` в RFC 1123, `itunes:duration`, когда длительность известна. Все URL в фиде MUST быть абсолютными.

#### Scenario: Фид отдаёт эпизоды в правильном порядке и с корректным enclosure

- **WHEN** в индексе есть эпизоды за 2026-10-01 и 2026-10-15, запрошен `GET /feed.xml`
- **THEN** XML валиден, первый item — эпизод 2026-10-15, у каждого item enclosure с URL `https://<host>/audio/<slug>`, точным размером в байтах, типом `audio/mpeg`, guid равен enclosure URL

#### Scenario: Пустой канал тоже валиден

- **WHEN** в папке нет эпизодов, запрошен `GET /feed.xml`
- **THEN** возвращается валидный RSS с метаданными канала и без items

### Requirement: Аудио стримится с поддержкой Range

`GET /audio/{slug}` MUST отдавать содержимое файла эпизода с корректным Content-Type и полной поддержкой HTTP Range (206 Partial Content для диапазонов, устойчивость к докачкам подкаст-приложений). Для неизвестного слага MUST возвращаться 404.

#### Scenario: Полное скачивание

- **WHEN** запрошен `GET /audio/pervyy-vypusk` без Range
- **THEN** ответ 200 с полным содержимым файла и Content-Type `audio/mpeg`

#### Scenario: Докачка с середины

- **WHEN** запрошен `GET /audio/pervyy-vypusk` с `Range: bytes=1000-1999`
- **THEN** ответ 206 со 1000 запрошенными байтами и корректным `Content-Range`

#### Scenario: Неизвестный эпизод

- **WHEN** запрошен `GET /audio/net-takogo`
- **THEN** ответ 404

### Requirement: Сайт показывает список эпизодов с плеером

`GET /` MUST возвращать HTML-страницу со списком эпизодов от новых к старым: дата, заголовок, описание, счётчики скачиваний и прослушиваний, элемент `<audio>` для прослушивания в браузере, ссылка на фид. Пустой список MUST отображаться осмысленной заглушкой.

#### Scenario: Эпизод виден на сайте

- **WHEN** в индексе есть эпизод «Первый выпуск», запрошен `GET /`
- **THEN** HTML содержит дату, заголовок, описание, `<audio>` с src на `/audio/pervyy-vypusk` и счётчики эпизода

#### Scenario: Пустой подкаст

- **WHEN** эпизодов нет, запрошен `GET /`
- **THEN** страница отображает заглушку «Эпизодов пока нет» и ссылку на фид

### Requirement: JSON API отдаёт машинный список эпизодов

`GET /api/episodes` MUST возвращать JSON-массив эпизодов от новых к старым с полями: slug, заголовок, описание, дата публикации, длительность, размер в байтах, счётчики скачиваний и прослушиваний, абсолютный URL аудио.

#### Scenario: Программный доступ к списку

- **WHEN** запрошен `GET /api/episodes`
- **THEN** ответ 200, Content-Type `application/json`, массив упорядочен от нового к старому, каждый элемент содержит перечисленные поля

### Requirement: Публичная поверхность доступна без авторизации

Фид, аудио, сайт и JSON API MUST быть доступны без аутентификации; единственная защищаемая точка — рескан, и тот может оставаться публичным (операция идемпотентна и безопасна). Ограничение доступа при необходимости решается на обратном прокси, вне кода сервиса.

#### Scenario: Всё публично

- **WHEN** анонимный клиент запрашивает `/`, `/feed.xml`, `/api/episodes`, `/audio/{slug}`
- **THEN** все ответы успешны без каких-либо заголовков аутентификации
