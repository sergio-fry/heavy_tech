# podcast-serving Specification

## Purpose

Публичная поверхность сервиса: RSS-фид для подкаст-приложений, стриминг аудио, HTML-сайт со списком эпизодов и плеером, JSON API — всё без авторизации, с абсолютными публичными URL.

## Requirements

### Requirement: RSS-фид совместим с подкаст-приложениями

`GET /feed.xml` MUST возвращать валидный RSS 2.0 с iTunes-расширением: метаданные канала из `podcast.yaml`; элементы — эпизоды с аудионосителем, новые сверху (по `published_at`); у каждого элемента enclosure на именованный аудио-URL `/audio/{номер}/{имя}.{ext}` с точным размером в байтах и MIME-типом по расширению файла, guid равен стабильному номерному URL `/audio/{номер}`, `pubDate` в RFC 1123, `itunes:duration`, когда длительность известна, `itunes:episode` равен номеру, а `description` содержит HTML, отрендеренный из markdown-описания эпизода и корректно экранированный в XML. Все URL в фиде MUST быть абсолютными.

#### Scenario: Фид отдаёт эпизоды в правильном порядке и с корректным enclosure

- **WHEN** в индексе есть эпизоды 3 (2026-10-01) и 7 (2026-10-15), запрошен `GET /feed.xml`
- **THEN** XML валиден, первый item — эпизод 7, у каждого item enclosure с именованным URL `https://<host>/audio/{номер}/{имя}.{ext}`, точным размером, типом по расширению, guid равен `https://<host>/audio/{номер}`, `itunes:episode` равен номеру

#### Scenario: Пустой канал тоже валиден

- **WHEN** в папке нет эпизодов, запрошен `GET /feed.xml`
- **THEN** возвращается валидный RSS с метаданными канала и без items

#### Scenario: Эпизод в AAC получает MIME по формату файла

- **WHEN** эпизод 4 имеет аудио `.aac` (MIME `audio/aac`), эпизод 5 — `.m4a` (MIME `audio/x-m4a`), запрошен `GET /feed.xml`
- **THEN** enclosure эпизода 4 имеет тип `audio/aac`, эпизода 5 — `audio/x-m4a`

#### Scenario: Описание в фиде — отрендеренный markdown

- **WHEN** описание эпизода 7 содержит markdown-разметку (выделение, ссылка), запрошен `GET /feed.xml`
- **THEN** XML валиден, `description` item'а после XML-разбора содержит HTML-теги (`<p>`, `<strong>`, `<a>`), исходная markdown-разметка в description не выводится

### Requirement: Видео-фид публикует выпуски с видео

`GET /feed-video.xml` MUST возвращать валидный RSS 2.0 с iTunes-расширением с теми метаданными канала из `podcast.yaml`, что и аудио-фид; элементы — эпизоды, у которых есть видеоноситель, новые сверху. У каждого элемента enclosure указывает на именованный видео-URL (`/video/{номер}/{имя}.{ext}`), guid равен стабильному номерному URL `/video/{номер}`, `itunes:episode` равен номеру эпизода. Эпизоды без видео в этом фиде MUST отсутствовать. Все URL абсолютные.

#### Scenario: Эпизод с видео в видео-фиде

- **WHEN** эпизод 7 имеет аудио- и видеоносители, запрошен `GET /feed-video.xml`
- **THEN** XML валиден, item содержит enclosure на `https://<host>/video/7/<имя>.{ext}` с точным размером и видео-MIME, guid равен `https://<host>/video/7`, `itunes:episode` = 7

#### Scenario: Аудио-выпуск не попадает в видео-фид

- **WHEN** эпизод 5 имеет только аудионоситель, запрошен `GET /feed-video.xml`
- **THEN** item для эпизода 5 в фиде отсутствует

### Requirement: Аудио стримится с поддержкой Range

`GET /audio/{номер}` и `GET /audio/{номер}/{имя}.{ext}` MUST отдавать содержимое аудионосителя эпизода с корректным Content-Type и полной поддержкой HTTP Range (206 Partial Content для диапазонов, устойчивость к докачкам подкаст-приложений). Content-Type MUST соответствовать MIME-типу носителя, сохранённому в индексе. Имя в третьем сегменте декоративное: поиск идёт по номеру, поэтому ранее опубликованные ссылки продолжают работать. Для неизвестного номера или эпизода без аудио MUST возвращаться 404.

#### Scenario: Полное скачивание

- **WHEN** эпизод 1 имеет аудио `.mp3`, запрошен `GET /audio/1` без Range
- **THEN** ответ 200 с полным содержимым файла и Content-Type `audio/mpeg`

#### Scenario: Докачка с середины

- **WHEN** запрошен `GET /audio/1` с `Range: bytes=1000-1999`
- **THEN** ответ 206 со 1000 запрошенными байтами и корректным `Content-Range`

#### Scenario: Неизвестный эпизод

- **WHEN** запрошен `GET /audio/999`
- **THEN** ответ 404

#### Scenario: Content-Type соответствует формату эпизода

- **WHEN** эпизод 4 имеет аудио `.aac`, запрошен `GET /audio/4` без Range
- **THEN** ответ 200 с Content-Type `audio/aac`; Range-запросы работают так же, как для MP3

#### Scenario: Именованный URL обслуживает аудио

- **WHEN** эпизод 1 имеет аудио `.mp3`, запрошен `GET /audio/1/001-<slug>.mp3` с `Range: bytes=0-99`
- **THEN** ответ 206 с Content-Type `audio/mpeg` и корректным `Content-Range`

### Requirement: Видео стримится с поддержкой Range

`GET /video/{номер}` и `GET /video/{номер}/{имя}.{ext}` MUST отдавать содержимое видеоносителя эпизода с корректным Content-Type (по расширению файла) и полной поддержкой HTTP Range. Имя в третьем сегменте декоративное: поиск идёт по номеру. Для неизвестного номера или эпизода без видео MUST возвращаться 404.

#### Scenario: Полная отдача видео

- **WHEN** эпизод 7 имеет видеоноситель `efir.mp4`, запрошен `GET /video/7` без Range
- **THEN** ответ 200 с полным содержимым файла и видео Content-Type

#### Scenario: Видео отсутствует

- **WHEN** запрошен `GET /video/5`, где эпизод 5 имеет только аудио
- **THEN** ответ 404

#### Scenario: Именованный URL обслуживает видео

- **WHEN** эпизод 7 имеет видео `efir.mp4`, запрошен `GET /video/7/007-<slug>.mp4`
- **THEN** ответ 200 с Content-Type `video/mp4` и полным содержимым файла

### Requirement: Markdown-описание рендерится в безопасный HTML

Описание выпуска (из `description.md` или из поля meta) MUST интерпретироваться как markdown и MUST выводиться HTML-разметкой: абзацы, переносы строк, списки, выделение, ссылки. Сырой HTML из исходника MUST не исполняться: активная разметка (скрипты, обработчики, произвольные теги) MUST быть экранирована или отброшена. Пустое или частично некорректное markdown-описание MUST не ломать страницу и не давать ошибку.

#### Scenario: Форматирование превращается в разметку

- **WHEN** описание эпизода 7 содержит `**важно**`, список из двух пунктов и ссылку `[гость](https://example.com)`, запрошен `GET /`
- **THEN** HTML карточки содержит `<strong>важно</strong>`, элементы списка и ссылку с адресом `https://example.com`

#### Scenario: Сырой HTML не исполняется

- **WHEN** описание содержит `<script>alert(1)</script>` и `<img src=x onerror=alert(1)>`
- **THEN** HTML страницы не содержит исполняемого тега `script` и атрибута-обработчика `onerror` из описания

#### Scenario: Пустое описание не ломает страницу

- **WHEN** у эпизода описания нет, запрошен `GET /`
- **THEN** страница отдаётся успешно, карточка эпизода выводится без блока описания

### Requirement: Медиа-URL содержит имя файла

Канонический URL носителя MUST иметь вид `/{audio|video}/{номер}/{имя}.{ext}`, где имя — номер, дополненный нулями до трёх цифр, и slug заголовка через дефис. Slug MUST быть транслитом заголовка в нижний регистр из символов `[a-z0-9-]`, обрезанным по границе слова до 60 символов; при пустом slug имя MUST состоять только из номера. `{ext}` MUST быть реальным расширением файла носителя. Именованный URL MUST обслуживать и стриминг, и скачивание.

#### Scenario: Видео-ссылка содержит имя файла

- **WHEN** эпизод 39 «Все фломастеры разные» имеет видео `efir.mp4`, запрошен `GET /`
- **THEN** ссылка на видео имеет вид `https://<host>/video/39/039-vse-flomastery-raznye.mp4`, ответ по ней — видео `video/mp4`, а имя сохранённого файла совпадает с последним сегментом URL

#### Scenario: Расширение аудио сохраняется

- **WHEN** эпизод 7 имеет аудио `zapis.m4a`, запрошена ссылка на аудио
- **THEN** URL оканчивается на `007-<slug>.m4a`, а ответ имеет Content-Type `audio/x-m4a`

#### Scenario: Длинный заголовок обрезается по слову

- **WHEN** заголовок выпуска даёт транслит длиннее 60 символов
- **THEN** slug обрезан до границы слова, не длиннее 60 символов, без завершающего дефиса

#### Scenario: Пустой slug

- **WHEN** заголовок выпуска 7 не даёт транслитерируемых символов, у эпизода есть аудио `zapis.m4a`
- **THEN** канонический URL — `/audio/7/007.m4a`

#### Scenario: Номерной URL продолжает работать

- **WHEN** эпизод 39 имеет видео, запрошен `GET /video/39`
- **THEN** ответ 200 с видеоносителем эпизода

#### Scenario: Старое имя после смены заголовка

- **WHEN** заголовок эпизода изменён, запрошен ранее опубликованный URL со старым slug
- **THEN** ответ 200 с тем же носителем (имя сегмента декоративное, поиск по номеру)

### Requirement: Страница содержит Open Graph-метаданные

Страницы `GET /`, `GET /episodes` и `GET /episodes/{номер}` MUST содержать Open Graph-теги для корректного превью при расшаривании: `og:title` (название канала для лендинга и архива, заголовок выпуска для страницы выпуска), `og:description` (описание канала или описание выпуска), `og:type` = `website` для лендинга и архива и `article` для страницы выпуска, `og:url` (канонический абсолютный URL страницы) и `og:image` (абсолютный URL обложки канала, когда она задана). Все значения MUST быть экранированы как HTML-атрибуты.

#### Scenario: Превью для мессенджера

- **WHEN** в `podcast.yaml` заданы название, описание и обложка, запрошен `GET /`
- **THEN** HTML содержит `og:title` с названием канала, `og:description` с описанием, `og:type` = `website`, `og:url` с базовым URL и `og:image` с абсолютным URL обложки

#### Scenario: Превью выпуска

- **WHEN** эпизод 7 имеет заголовок и описание, запрошен `GET /episodes/7`
- **THEN** HTML содержит `og:title` с заголовком выпуска, `og:description` с описанием выпуска, `og:type` = `article` и `og:url` с абсолютным URL страницы выпуска

#### Scenario: Обложка не задана

- **WHEN** в `podcast.yaml` поле `image` пусто, запрошен `GET /`
- **THEN** HTML содержит `og:title`, `og:description`, `og:type` и `og:url`, а тег `og:image` отсутствует

### Requirement: JSON API отдаёт машинный список эпизодов

`GET /api/episodes` MUST возвращать JSON-массив эпизодов от новых к старым с полями: номер, заголовок, описание как markdown-исходник, дата публикации, ведущий и гости (строка и список строк; пустая строка и пустой список, когда не заданы), ссылка на YouTube (пустая строка, когда не задана), доступные носители (kind, абсолютный канонический URL с именем файла, размер в байтах, длительность), счётчики скачиваний раздельно по audio и video и их сумма, счётчик прослушиваний, число просмотров YouTube (`youtube_views`, 0 когда неизвестно) и главы (`chapters`: массив объектов `{start, title}`, пустой массив когда глав нет).

#### Scenario: Программный доступ к списку

- **WHEN** запрошен `GET /api/episodes`
- **THEN** ответ 200, Content-Type `application/json`, массив упорядочен от нового к старому, каждый элемент содержит перечисленные поля, включая ведущего, гостей, именованные URL носителей, разбивку скачиваний по носителям, сумму, ссылку на YouTube, просмотры YouTube и главы

#### Scenario: Участники в API

- **WHEN** эпизод 45 имеет `host: Сергей Удалов` и `guests: [Мила Шведова]`, у эпизода 6 поля не заданы, запрошен `GET /api/episodes`
- **THEN** у элемента 45 `host` = «Сергей Удалов» и `guests` = [«Мила Шведова»], у элемента 6 `host` — пустая строка и `guests` — пустой список

#### Scenario: YouTube-ссылка в API

- **WHEN** у эпизода 7 задана YouTube-ссылка, у эпизода 6 — нет, запрошен `GET /api/episodes`
- **THEN** у элемента 7 поле `youtube` содержит заданный URL, у элемента 6 — пустую строку

#### Scenario: YouTube-метрики в API

- **WHEN** у эпизода 7 известны 100 просмотров YouTube и две главы, запрошен `GET /api/episodes`
- **THEN** у элемента 7 `youtube_views` = 100, `chapters` содержит две записи с полями `start` и `title`; у эпизода без глав `chapters` — пустой массив

#### Scenario: Описание в API остаётся markdown-исходником

- **WHEN** описание эпизода 7 содержит `**важно**`, запрошен `GET /api/episodes`
- **THEN** поле `description` содержит исходный markdown-текст, HTML-разметка в нём не выводится

### Requirement: Публичная поверхность доступна без авторизации

Фиды, аудио, видео, сайт и JSON API MUST быть доступны без аутентификации; единственная защищаемая точка — рескан, и тот может оставаться публичным (операция идемпотентна и безопасна). Ограничение доступа при необходимости решается на обратном прокси, вне кода сервиса.

#### Scenario: Всё публично

- **WHEN** анонимный клиент запрашивает `/`, `/feed.xml`, `/feed-video.xml`, `/api/episodes`, `/audio/{n}`, `/video/{n}`
- **THEN** все ответы успешны без каких-либо заголовков аутентификации

### Requirement: Лендинг канала на главной странице

`GET /` MUST возвращать лендинг канала: название, описание или `tagline`, обложку, текст из `about.md`, три последних выпуска, подборку `start_here` и действия подписки. Каждый выпуск MUST ссылаться на `/episodes/{номер}`. Действие «слушать последний выпуск» MUST запускать воспроизведение самого нового выпуска с аудио в едином плеере без перехода на другую страницу. Пустой каталог MUST показывать заглушку и ссылку на фид.

#### Scenario: Текст лендинга и промо

- **WHEN** канал имеет `about.md` с заголовком и абзацем, запрошен `GET /`
- **THEN** страница содержит отрендеренный заголовок и абзац из `about.md`, название, описание и действия подписки

#### Scenario: Последние выпуски и переходы

- **WHEN** в индексе 10 выпусков, запрошен `GET /`
- **THEN** лендинг показывает три последних выпуска, каждый со ссылкой на свою страницу `/episodes/{номер}`, и ссылку на полный архив `/episodes`

#### Scenario: Подборка «с чего начать»

- **WHEN** `podcast.yaml` задаёт `start_here: [7, 3]`, оба выпуска существуют, запрошен `GET /`
- **THEN** лендинг показывает выпуски 7 и 3 в указанном порядке со ссылками на их страницы

#### Scenario: Без about.md

- **WHEN** файла `about.md` нет, запрошен `GET /`
- **THEN** лендинг показывает описание канала из `podcast.yaml`, страница отдаётся успешно

#### Scenario: Пустой каталог

- **WHEN** эпизодов нет, запрошен `GET /`
- **THEN** страница показывает заглушку «Выпуски скоро появятся» и ссылку на фид

#### Scenario: Слушать последний выпуск

- **WHEN** самый новый выпуск с аудио — 7, на лендинге нажато «Слушать последний выпуск»
- **THEN** выпуск 7 начинает воспроизводиться в едином плеере, страница не перезагружается

### Requirement: Архив выпусков

`GET /episodes` MUST возвращать архив всех выпусков от новых к старым компактными строками без поиска и фильтров: номер, дата, заголовок, участники, длительность аудио, единый счётчик (когда больше нуля) и переход на страницу выпуска. Длительность MUST быть помечена иконкой часов, единый счётчик — иконкой и доступной подписью, объясняющей смысл числа. Строка выпуска с аудио MUST содержать быстрые действия «слушать» и «скачать» аудиофайл; выпуск без аудио — без них, со ссылкой на свою страницу.

#### Scenario: Полный список

- **WHEN** в индексе 49 выпусков, запрошен `GET /episodes`
- **THEN** страница содержит все 49 выпусков от новых к старым, у каждого — номер, дата, заголовок и ссылка на страницу выпуска; на странице нет поля поиска и фильтров

#### Scenario: Быстрое прослушивание

- **WHEN** у выпуска 7 есть аудио, на странице `/episodes` нажата кнопка «слушать» выпуска 7
- **THEN** воспроизведение запускается в едином плеере без перехода на страницу выпуска; размер файла в строке архива не показан

#### Scenario: Быстрое скачивание

- **WHEN** у выпуска 7 есть аудио, активирована ссылка быстрого скачивания из строки выпуска 7
- **THEN** отдаётся аудиофайл выпуска, ссылка содержит атрибут скачивания

#### Scenario: Пометки цифр

- **WHEN** выпуск с аудио длительностью 31:12 и счётчиком 42 отображается в архиве
- **THEN** длительность помечена иконкой часов, счётчик — иконкой с доступной подписью, что это прослушивания и просмотры

#### Scenario: Выпуск без аудио

- **WHEN** выпуск 5 имеет только видео, запрошен `GET /episodes`
- **THEN** строка выпуска 5 не содержит кнопок «слушать» и «скачать», но ссылается на свою страницу выпуска

### Requirement: Страница выпуска

`GET /episodes/{номер}` MUST возвращать страницу выпуска: заголовок, номер, дата, участники, единый счётчик, полные шоу-ноуты, плеер с главами, действия скачивания с размером и атрибутом `download`, ссылку на YouTube, действие «поделиться» и переходы к предыдущему и следующему выпуску. Неизвестный номер MUST давать 404. Страница MUST содержать канонический URL выпуска. Выпуск без аудио MUST отображаться без плеера.

#### Scenario: Полная страница выпуска

- **WHEN** эпизод 7 имеет аудио, видео, описание и главы, запрошен `GET /episodes/7`
- **THEN** ответ 200, страница содержит заголовок, дату, участников, полные шоу-ноуты, плеер с главами, ссылки «скачать» на именованные URL с размерами и атрибутом `download`

#### Scenario: Неизвестный выпуск

- **WHEN** запрошен `GET /episodes/999`
- **THEN** ответ 404

#### Scenario: Поделиться выпуском

- **WHEN** на странице выпуска 7 нажато «Поделиться», браузер поддерживает Web Share API
- **THEN** в системный диалог передаются заголовок выпуска и абсолютный URL `/episodes/7`

#### Scenario: Переходы между выпусками

- **WHEN** в индексе есть выпуски 6, 7 и 9, запрошен `GET /episodes/7`
- **THEN** страница ссылается на выпуск 9 как следующий и на выпуск 6 как предыдущий по порядку публикации

#### Scenario: Выпуск без аудио

- **WHEN** эпизод 5 имеет только видеоноситель, запрошен `GET /episodes/5`
- **THEN** страница отдаётся успешно, аудиоплеер отсутствует, ссылка на скачивание видео присутствует

### Requirement: Единый плеер с закреплённой мини-панелью

Страница MUST использовать не более одного активного аудиоплеера: запуск другого выпуска MUST переключать существующий, а не создавать второй. При уходе инлайн-плеера за пределы экрана MUST появляться закреплённая мини-панель с названием выпуска, play/pause, перемоткой и временем. Закрытие панели MUST останавливать воспроизведение. Нативный `<audio controls>` MUST NOT использоваться.

#### Scenario: Переключение выпуска

- **WHEN** играет выпуск 7, слушатель нажимает play у выпуска 6
- **THEN** выпуск 7 останавливается, выпуск 6 начинает играть в том же единственном плеере

#### Scenario: Мини-панель при скролле

- **WHEN** выпуск играет, а его инлайн-плеер ушёл за пределы экрана
- **THEN** появляется закреплённая панель с названием выпуска и управлением; при возврате к инлайн-плееру панель скрывается

#### Scenario: Закрытие панели

- **WHEN** слушатель закрывает мини-панель
- **THEN** воспроизведение останавливается, панель исчезает

### Requirement: Плеер продолжает с места остановки и меняет скорость

Плеер MUST сохранять позицию воспроизведения по каждому выпуску и при повторном запуске продолжать с неё, если позиция больше 5 секунд и до конца осталось больше 10 секунд; иначе воспроизведение MUST начинаться сначала. Действие «начать сначала» MUST сбрасывать сохранённую позицию. Скорость MUST переключаться по кругу 1 / 1.25 / 1.5 / 1.75 / 2x и сохраняться между визитами.

#### Scenario: Продолжение после возврата

- **WHEN** слушатель остановил выпуск 7 на 12:34, закрыл страницу и снова нажал play
- **THEN** воспроизведение начинается с 12:34, в плеере доступно действие «начать сначала»

#### Scenario: Начало сначала

- **WHEN** слушатель нажал «начать сначала» на позиции 12:34
- **THEN** воспроизведение начинается с 0:00

#### Scenario: Скорость сохраняется

- **WHEN** слушатель выбрал 1.5x и перезагрузил страницу
- **THEN** плеер показывает 1.5x и воспроизводит с этой скоростью

### Requirement: Плеер управляется клавиатурой и доступен с телефона

Прогресс-бар плеера MUST быть фокусируемым элементом с ролью слайдера, доступным именем и текущим значением, MUST перематывать стрелками клавиатуры на 15 секунд и MUST иметь область касания не меньше 44 px по высоте. Кнопки управления MUST иметь текстовые или aria-имена, а видимый фокус MUST сохраняться.

#### Scenario: Перемотка с клавиатуры

- **WHEN** прогресс-бар в фокусе, нажата стрелка вправо
- **THEN** воспроизведение перематывается на 15 секунд вперёд

#### Scenario: Доступное имя и значение

- **WHEN** страница выпуска отрендерена
- **THEN** прогресс-бар имеет роль слайдера, aria-имя и aria-значение текущей позиции

#### Scenario: Область касания

- **WHEN** страница открыта на телефоне
- **THEN** высота области перемотки не меньше 44 px

### Requirement: Главы показываются отдельно от описания

Главы эпизода MUST отображаться в плеере отдельным раскрываемым разделом, скрытым по умолчанию, и MUST NOT входить в краткое описание или шоу-ноуты. Клик по главе MUST перематывать воспроизведение на её начало. При отсутствии глав раздел MUST отсутствовать.

#### Scenario: Главы скрыты по умолчанию

- **WHEN** у эпизода 7 есть три главы, запрошен `GET /episodes/7`
- **THEN** страница содержит раздел «Главы», закрытый по умолчанию, а текст шоу-ноутов не содержит списка глав

#### Scenario: Переход по главе

- **WHEN** слушатель открыл главы и выбрал главу «Основная часть» с началом 12:30
- **THEN** воспроизведение перематывается на 12:30

#### Scenario: Глав нет

- **WHEN** у эпизода 7 главы не извлечены, запрошен `GET /episodes/7`
- **THEN** раздел «Главы» на странице отсутствует

### Requirement: Плеер объявляет метаданные в Media Session

При воспроизведении плеер MUST публиковать в Media Session API название выпуска, название канала и обложку канала, а также обрабатывать системные действия play, pause, перемотки назад и вперёд на 15 секунд. Если API недоступен, воспроизведение MUST работать без ошибок.

#### Scenario: Метаданные для локскрина

- **WHEN** начато воспроизведение выпуска 7 на устройстве с Media Session API
- **THEN** метаданные содержат заголовок выпуска, название канала и абсолютный URL обложки

#### Scenario: Системная перемотка

- **WHEN** пользователь нажал «вперёд» в системном интерфейсе
- **THEN** воспроизведение перематывается на 15 секунд вперёд

### Requirement: Карта сайта и robots

`GET /sitemap.xml` MUST отдавать XML-карту сайта со всеми публичными страницами: лендинг, архив и страница каждого выпуска, с абсолютными URL из `base-url` и датой публикации выпуска. `GET /robots.txt` MUST разрешать обход и указывать абсолютный URL карты сайта. Карта MUST обновляться при изменении набора выпусков.

#### Scenario: Карта содержит страницы выпусков

- **WHEN** в индексе есть выпуски 7 и 9, запрошен `GET /sitemap.xml`
- **THEN** ответ 200 с XML, содержащим абсолютные URL `/`, `/episodes`, `/episodes/7` и `/episodes/9`

#### Scenario: robots указывает карту

- **WHEN** запрошен `GET /robots.txt`
- **THEN** ответ разрешает обход и содержит строку `Sitemap` с абсолютным URL `/sitemap.xml`

#### Scenario: Удалённый выпуск исчезает из карты

- **WHEN** эпизод 7 удалён из папки и выполнен рескан, запрошен `GET /sitemap.xml`
- **THEN** URL `/episodes/7` в карте отсутствует

### Requirement: Страницы содержат поисковую разметку

Каждая HTML-страница MUST содержать уникальный `<title>`, meta description, абсолютный `<link rel="canonical">` и RSS autodiscovery. Лендинг MUST содержать JSON-LD `PodcastSeries` с названием, описанием, URL и обложкой канала; страница выпуска — JSON-LD `PodcastEpisode` с заголовком, датой публикации, длительностью аудио и принадлежностью сериалу. Все значения MUST быть экранированы как HTML.

#### Scenario: Уникальный заголовок выпуска

- **WHEN** эпизод 7 имеет заголовок «Аким Губанов», запрошен `GET /episodes/7`
- **THEN** `<title>` содержит заголовок выпуска, canonical указывает на абсолютный `/episodes/7`, meta description содержит описание выпуска

#### Scenario: JSON-LD выпуска

- **WHEN** запрошен `GET /episodes/7`
- **THEN** страница содержит валидный JSON-LD `PodcastEpisode` с датой, длительностью и ссылкой на сериал

#### Scenario: JSON-LD лендинга

- **WHEN** запрошен `GET /`
- **THEN** страница содержит валидный JSON-LD `PodcastSeries` с названием, описанием, URL и обложкой канала

### Requirement: Подписка на платформы

Действия подписки MUST строиться из `links` в порядке, заданном в `podcast.yaml`: каждая ссылка открывается в новой вкладке с `rel="noopener noreferrer"`. При отсутствии `links` MUST оставаться действие копирования RSS-ссылки; копирование MUST быть доступно на всех страницах с блоком подписки. Копирование MUST показывать подтверждение.

#### Scenario: Кнопки платформ

- **WHEN** `podcast.yaml` задаёт ссылки Apple Podcasts и Telegram, запрошен `GET /`
- **THEN** лендинг показывает две кнопки в заданном порядке с абсолютными URL и `target="_blank"`

#### Scenario: Ссылок нет

- **WHEN** `links` не заданы, запрошен `GET /`
- **THEN** лендинг показывает действие копирования RSS и не показывает кнопок платформ

#### Scenario: Копирование RSS

- **WHEN** слушатель нажал «Скопировать RSS»
- **THEN** абсолютный URL `/feed.xml` попадает в буфер обмена, появляется подтверждение
